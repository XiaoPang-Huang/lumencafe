# 02 · 对话功能（Chat）

## 1. 功能描述

对话功能分两层对象：**Chat 应用（助手）** 与 **会话（Conversation）**。Chat 应用是带配置（模型、提示词、知识库绑定）的实体，会话是其下的具体对话。路由设计：

- 应用列表：`/chats`
- 对话页：`/chat/:chatId?conversationId=xxx&isNew=true`（当前会话用 URL query 表达，可分享、刷新保持）
- 分享页：`/chats/share?shared_id=xxx&from=chat&auth=...`（无布局）
- 嵌入 Widget：`/chats/widget`（透明底壳，供 iframe 嵌入第三方站点）

证据：`web/src/routes.tsx` L47-49、134-147、L296；`hooks/use-chat-url.ts`。

## 2. 页面布局说明

### 2.1 Chat 应用列表页（`/chats`）

标准四段式列表页（证据：`pages/next-chats/index.tsx`）：

```
┌──────────────────────────────────────────────┐
│ 💬 Chat Apps │ ⛛所有者筛选 │ 🔍搜索 │ [+ 创建 Chat] │
├──────────────────────────────────────────────┤
│ [ChatCard: 头像+名称+描述+更新时间 ⋯] × N       │
├──────────────────────────────────────────────┤
│                  ‹ 分页 ›                     │
└──────────────────────────────────────────────┘
```

- 卡片复用通用 `HomeCard`：头像 / 名称（超长省略+tooltip）/ 描述 / 更新时间；右上角 MoreButton 下拉 = 重命名、删除（`ConfirmDeleteDialog` 二次确认）；共享卡片显示 `SharedBadge`。
- 空态：`EmptyAppCard` 整卡可点击即创建；`?isCreate=true` 自动弹创建对话框。
- 创建/重命名共用一个 `RenameDialog`（只需名称，其余走默认值）。默认配置证据：`hooks/use-create-chat.ts`——默认模型、开场白模板、`similarity_threshold: 0.2`、`top_n: 8` 等。

主区 Card 内三种视图互斥切换：多模型对比（最多 3 个并排）/ 助手设置表单 / 单聊（默认）。`conversationId` 是**唯一事实来源**：URL 驱动会话切换，切换时先清空旧消息再拉取，防泄漏（源码注释明确）。

### 2.3 消息气泡（证据：`components/message-item/index.tsx`）

- Assistant 居左、User 居右；双方都有头像（用户真实头像，助手用应用图标或内置 SVG）。
- 正文统一走 `MarkdownContent`：react-markdown + rehypeRaw + 自定义消毒 + KaTeX 数学 + 代码高亮 + DOMPurify；用户消息关闭数学解析（`$` 按字面）。
- **思维链**：SSE 的 `start_to_think/end_to_think` 事件在 `utils/chat.ts` 的 `mergeAnswerChunk` 拼成 `<think>` 标签，渲染前转 `<details>/<summary>` 折叠块（Thinking... / Thought）。
- **引用块**：正文中的 `[1]` / `[ID:1]` 标记（正则匹配）替换为 HoverCard——悬浮看 chunk 原文 + 文档名 + 缩略图；点击文档名打开 PDF 抽屉（`PdfSheet`）并**定位到原文位置**；网页文档直接新开窗口。
- 答案下方显示 `TurnUsage`（token 用量 + 耗时）；生成文件可下载（`DocumentDownloadButton`）。
- 流式中且内容为空时显示 `LoadingDots` 三点动画；流停顿由 `useLoadingPause` 控制。

### 2.4 输入区（证据：`components/message-input/next.tsx`）

胶囊形输入卡片（`rounded-[28px]`），能力矩阵：

| 能力 | 说明 |
|---|---|
| 文本 | Enter 发送 / Shift+Enter 换行；排除输入法合成状态（`isComposing`）；autoSize 1~8 行 |
| 附件 | 「+」菜单或拖拽上传，最多 5 个 × 5MB，横向缩略列表可单个删除 |
| 联网搜索 | 「+」菜单开启后出现可移除的 "Web search" chip，随消息发送 |
| 思维档位 | 两档 Select：Agentic（5）/ None（0），持久化到 storage |
| 语音 | AudioButton 语音识别填入并自动发送 |
| 发送/停止 | 发送中按钮变停止键（`CircleStop`），调 `stopOutputMessage` 中止 |
| 高度调节 | 可拖拽调整输入框高度（40~400px） |

### 2.5 会话侧栏（Sessions）（证据：`chat/sessions.tsx`）

- 顶部：助手名（可折叠侧栏）+ New conversation / Settings / Multiple models 三个导航按钮。
- 中部：`Conversations (total)` 计数 + 进入批量选择模式（Checkbox 多选 + 全选 + ConfirmDeleteDialog 批量删除，同时中止在途流）+ 搜索框（滚动加载）。
- 列表项悬停显示 MoreButton → 目前**仅删除**。无归档功能，删除即物理删除。
- 删除当前打开会话后自动清空 URL 参数回列表态。

## 3. 用户操作流程

### 3.1 发起新对话（懒创建会话）

```
点「New conversation」→ 前端生成本地临时 id 写入 URL (?isNew=true)
→ 列表头部插入临时会话项（内嵌 prologue 开场白消息）
→ 用户输入发送 → 先落库创建真实会话 → URL 换成后端真实 id
→ 流式返回答案
```

设计要点：**发送时才真正创建会话**，避免空会话垃圾数据。prologue 开场白作为第一条 assistant 消息预置（幂等 seed，`id` 前缀 `prologue_`），第一条消息不显示操作条。

### 3.2 流式收发（核心链路）

```
handlePressEnter
  → appendQuestion（user 消息 + assistant 占位入 store）
  → runChatCompletionStream
      原生 fetch POST /api/v1/chat/completions（axios 拿不到 ReadableStream，故用 fetch）
      → response.body.pipeThrough(TextDecoderStream)
                        .pipeThrough(EventSourceParserStream())
      → mergeAnswerChunk 增量拼接 / final 整段替换 / think 标签插入
      → 每 60ms（AnswerFlushIntervalMs）或 final 时 applyAnswer 节流写入 store
  → 停止：abortController.abort()
  → 失败：问题存入 pendingInput，回到会话且输入框为空时回填重试
```

状态管理（证据：`pages/next-chats/chat-stream/store.ts`）：zustand 模块级 store，**页面卸载后流仍继续写入**（返回时重新订阅）；按 conversationId 分 session，LRU 上限缓存 10 个会话，流式中的会话永不驱逐；会话切换时 `hydrateFromServer` 有防截断/防泄漏守卫（流式中拒绝覆盖、服务端列表比本地短时拒绝）。

消息列表用 @tanstack/react-virtual 虚拟化，长对话不卡。

### 3.3 消息交互（证据：`components/message-item/group-button.tsx`）

| 操作 | 交互 |
|---|---|
| 复制（assistant） | 自动去除思维链后复制 |
| 语音朗读 | TTS 朗读/暂停 |
| 点赞 | 直接上报 |
| 点踩 | 打开 FeedbackDialog 填反馈 |
| 查看提示词 | PromptDialog（当消息带 prompt 时） |
| 复制（user） | 直接复制 |
| 重新生成 | 把原问题作为新 turn 重发，旧答案保留 |
| 删除消息 | 若删除的是正在被回答的问题，先 abort 在途流 |

操作条悬停显形（`opacity-0 group-hover:opacity-100`）。

### 3.4 分享与嵌入

- 对话页「Embed into site」→ EmbedDialog 生成 iframe 代码，参数支持主题/语言/头像显隐。
- 分享页隐藏点赞与朗读；支持重置对话；联网开关取决于服务端配置。

### 3.5 多模型对比

底部公共输入框回车 → 通过 `useImperativeHandle` 收集所有卡片 ref 同时发送（最多 3 个模型并排）；每卡可换模型、可把该卡配置「应用配置到助手」。

## 4. 可借鉴的设计要点总结

1. **会话懒创建**：发送时才落库，杜绝空会话；临时 id 无缝换真实 id。
2. **URL 即会话状态**：conversationId 放 query，刷新/分享/回退全部自然成立。
3. **模块级流式 store**：切页不中断生成；LRU 缓存 + 流式会话防驱逐；hydrate 守卫防截断。这是「对话页独立 store 挂在组件上」最容易踩的三个坑的完整解法。
4. **60ms 节流渲染**：SSE chunk 合并后按帧批量写 store，避免 Markdown 每 chunk 全量重渲染。
5. **思维链转折叠块**：协议层 `think` 标记 → 渲染层 `<details>`，零第三方依赖。
6. **引用三级呈现**：行内标记 → 悬浮卡（原文摘要）→ 点击进 PDF 定位；信息密度逐层放开。
7. **停止键复用发送位**：发送/停止同一按钮位，减少误触。
8. **失败回填**：pendingInput 机制让「网络断了的问题」不丢。
9. **prologue 幂等种子**：开场白用固定 id 前缀，重复进入不重复注入。
