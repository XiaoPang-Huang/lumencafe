## 一、范围（按执行顺序）

### 1. postgres / caddy 镜像 digest 跟移（拍板回执项，最先做）

- 先出 D13 影响面评估：新 digest 的构建 changelog、风险面、回退 = 旧 digest（旧值在 docker-compose.yml 注释里留档）。
- 跟移到当前官方最新 digest（postgres:18-alpine / caddy:2-alpine 同 tag）。
- 跟移后用 trivy 层扫确认「可修高危清零」；扫不过的停下报需求会话，不硬上。

### 2. Dockerfile 镜像自带包清理（拍板回执项，并入本步）

- 镜像自带 4 个有修复版的包（msgpack / setuptools / urllib3 等，以 trivy 层扫实测为准）：
  - 未被项目引用的 → Dockerfile 收尾 `pip uninstall`；
  - 确属传递依赖的 → 进 lockfile 锁安全版（走第 3 条的 in→compile 机制）。

### 3. 共享 httpx 总机

- 新建 `app/services/http_client.py`：lifespan 建/销毁 `httpx.AsyncClient`（超时与连接池参数显式写明）。
- `llm_gateway.py` 每调用新建 client 处全部改用总机；`papers_crawl.py` 等外部调用同改。
- 注意：mock 链路不联网，不受影响，但代码路径要一致走总机。

### 4. tenacity 重试收口

- 新包按 D14 选最安全版本入 `requirements.in`，`uv pip compile --universal --generate-hashes` 重新生成 lockfile（新包连带刷新哈希）。
- 装饰/包装：NCBI esearch/efetch、LLM 瞬时错误（网络类/5xx/429），替 `papers_crawl.py` 手写 sleep 重试。
- 不做无差别重试：4xx（除 429）、鉴权错误不重试。

### 5. nh3 + markdown-it-py 统一渲染出口

- 新建 `app/services/render_service.py`：markdown-it-py 渲染 → nh3 消毒，函数级落地 + 单测。
- 本期只落函数不接线（真前端启用时再接到 chat/论文预览/笔记出口），代码里注明启用点。

### 6. 附带修复（QA 小坑）

- `backend/tests/conftest.py` TRUNCATE 清单补 `user_skills` 表（迁移 0003 后共 22 表）。
