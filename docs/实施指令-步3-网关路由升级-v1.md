## 一、目标

路由策略从「全局默认」升级为「按消费者路由」（D12）：调用方传 `app_key` → 引擎解析主模型 + 有序备用链 → 首 token 前失败按序兜底 → 主模型连挂自动熔断、恢复自动切回 → 每次调用写 `llm_call_logs` 计量。

## 二、任务分解（按序执行）

### 1. Alembic 0004（只增不改旧）

- 新表 `model_assignments`：app_key（唯一）、primary_model_id、fallback 备用链（有序 JSONB 或关联表，由架构师定，见 Q1）、enabled。
- 新表 `llm_call_logs`：app_key、model_id、token 进/出、耗时、成败、错误摘要、费用（单价快照 × token，Langfuse 算法）。
- 单价字段：挂 `llm_models.meta` 或独立列（Q1，架构师定）。
- 种子：为现有 app_key（chat / money_parse / polish）各建一行，主模型 = 当前默认路由。

### 2. 路由解析 `route_service.resolve_for(app_key)`

- 演进自 `resolve_default()`；未配置指派的应用回落默认路由（兼容期不报错）。
- 兜底边界：只管「首 token 前」的失败；流式开始输出后不换模型（所有同类产品同限制）。
- 调用面改造：`chat_service` / `money_service`（AI 记一笔）/ `polish` 传 app_key；对外 `/gw/v1` 不加指派概念（model 参数直查照旧，B1）。

### 3. 熔断（语义抄 Portkey，参数 Q2：连挂 N 次摘出、冷却、探测恢复自动切回；先简单后精细）

- 状态存库（别只存内存，重启不丢）。
- mock provider 模式下熔断逻辑照常可测（用失败注入）。

### 4. 记账出口

- `chat_once` / `chat_stream` / 未来 `embeddings` 出口统一写 `llm_call_logs`；mock 模式记 0 或跳过（B1）。
- 费用 = token × 单价快照（调用时固化单价，事后改单价不动历史账）。

### 5. `#/admin` 扩展（两个新页签）

- **模型指派页**：app_key → 主模型 + 备用链（有序编辑）。
- **用量统计页**：one-api 式布局（渠道/令牌/额度/日志），先用卡片 + 表格（Q6），时间筛选。
- 界面动工前按 AGENTS.md §一 对照 one-api 案例（渠道管理已是既定参考对象）。

### 6. 测试

- 新用例：指派解析、兜底切换、熔断触发/恢复、记账对账、权限（非 admin 不可见统计）。
- 回归：既有 100 用例全绿。
