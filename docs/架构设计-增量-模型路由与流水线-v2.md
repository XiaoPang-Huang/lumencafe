## Part B 设计要点

### B1 网关路由升级

- 调用面约定：各业务调用引擎时传 `app_key`（chat / money_parse / papers_translate / papers_qa / polish / embedding…），引擎查 model_assignments 解析主模型 + 备用链；
- `route_service.resolve_default()` 演进为 `resolve_for(app_key)`；未配置指派的应用回落默认路由（兼容期）；
- 兜底只管「首 token 前」的失败（流式开始输出后不可换模型——所有同类产品同限制）；
- 熔断：主模型连挂 N 次自动摘出旋转、备用顶上、探测恢复后自动切回（参数 N 与探测频率开工时定）；
- 记账：chat_once/chat_stream/embeddings 出口统一写 llm_call_logs（含 usage；mock 模式记 0 或跳过）；
- 对外 `/gw/v1` 不加指派概念（model 参数直查照旧），与内部 app_key 路由并行不悖。

### B2 Hatchet 流水线

- docker-compose 增 hatchet-engine 服务，PG 用现有实例独立库名；
- 论文域首批三条：每日抓取（替 /internal/jobs/papers-crawl 手动触发）、解析任务轮询、digest 推送；
- 幂等键落库（收编 Q11 进程内当日标记）；
- 管理页可查看运行状态（链接进 /admin/hatchet 子路径控制台）。

### B3 工程三小件

- 共享 httpx client：`app/services/http_client.py`，lifespan 建/销毁，网关/抓取/未来 MinerU、Unpaywall 共用；
- tenacity：装饰 NCBI esearch/efetch、Unpaywall、MinerU 提交/轮询、LLM 瞬时错误（替 papers_crawl.py:344 手写重试）；
- nh3：建统一渲染服务（markdown-it-py 渲染 → nh3 消毒），chat/论文预览/笔记共用；真前端前可先用于后端任何输出 HTML 的口子。

### B4 明确不做

- 不引入 LiteLLM/one-api/Portkey/Langfuse 任何服务（只抄设计，见《组件选型》第四部分）；
- 不上 Prefect/Airflow/Windmill；
- 不另开任何管理端口/Web；
- 统计不上 Prometheus/Grafana（PG 聚合查询即够）。
