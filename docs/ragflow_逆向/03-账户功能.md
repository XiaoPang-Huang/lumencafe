# 03 · 账户功能（注册 / 登录 / 用户设置 / 权限管理）

## 1. 功能描述

账户体系分布在三个独立子系统：用户端认证（`/login-next`）、用户设置中心（`/user-setting/*` + `/integrations/*` + `/team`）、管理后台（`/admin/*`，独立子应用）。开源版是「邮箱 + 密码单因子」极简形态：无验证码、无 OAuth 按钮、无邮箱验证交互；权限系统通过 `ee-stub` 位掩码接缝为企业版预留，OSS 恒视为资源 Owner。

## 2. 页面布局说明

### 2.1 登录 / 注册页（证据：`pages/login-next/index.tsx`、`card.tsx`、`bg.tsx`）

- **登录与注册是同一张卡片的 3D 翻转而换面**（`FlipCard`：`rotate-y-180` 过渡，`backface-visibility` 探测降级），注册成功 toast 后翻回登录面。
- 背景：`BgSvg` 动画 + `Spotlight` 光晕；提交按钮金属渐变（`bg-metallic-gradient`）。
- 表单字段：邮箱 + 密码 + 昵称（仅注册）+ Remember me。zod schema + `superRefine` 动态校验：昵称允许任何语言的字母/数字及空格 `._'-`（`NICKNAME_PATTERN = /^[\p{L}\p{N} ._'-]+$/u`，上限 100 字符）。
- **注册开关由后端系统配置驱动**：`registerEnabled` 关闭时隐藏 "Sign up"（带 200ms 翻牌动画）。
- 已登录用户访问登录页自动跳首页。

### 2.2 个人设置（Profile）（证据：`pages/user-setting/profile/index.tsx`）

「标签行 + 只读框 + Edit 按钮」的概览式布局，每项点 Edit 弹 480px Modal 编辑：

| 项目 | 可改性 | 细节 |
|---|---|---|
| 用户名 | 可改 | trim / 1-100 字符 / 昵称正则；`PATCH /users/me` |
| 头像 | 可改 | 选图（jpg/png/webp/bmp ≤4MB）→ 300×300 裁剪弹窗（拖动+滚轮缩放）→ canvas 输出 **64×64 PNG base64** 即传即存；右上角 X 移除 |
| 时区 | 可改 | 搜索下拉，`Intl.supportedValuesOf('timeZone')` 按偏移排序，格式 `GMT+08:00 Asia/Shanghai`，默认浏览器时区 |
| 邮箱 | **只读** | 纯展示 + 说明文案 |
| 密码 | 条件可改 | 仅密码渠道登录用户可见（OAuth 用户隐藏）；三字段弹窗，新密码 min 8，两次一致校验 |

语言与主题**不在 Profile 页**：语言切换在侧边栏底部用户下拉的子菜单（当前语言加粗）；主题为 Dark/Light 项。

### 2.3 API Key 管理（证据：`components/api-service/`）

- 页面 = 「RAGFlow API」卡（后端地址 + 复制按钮）+ 懒加载的 Markdown API 文档（230KB，首帧后渲染，带目录）+ Langfuse 观测卡 + Key 管理弹窗。
- Key 表格三列：Token（**完整明文，不脱敏**）/ Created / Action。
- 上限 **16 个**；创建按钮超限置灰。
- 复制反馈：复制成功图标变绿勾 2 秒 + Tooltip "copied"。
- 删除：垃圾桶 → 二次确认 → toast。

### 2.4 团队与权限（证据：`pages/user-setting/setting-team/`、`ee-stub/constants/team.ts`）

- 页面标题为「{昵称} 的工作空间」，上下两张 Card：团队成员 / 加入的团队。
- 邀请成员：单邮箱字段弹窗 → 被邀请人进入 `Invited` 状态，可同意/拒绝；已加入团队可退出（确认后执行）。
- 角色种类：`Owner / Invite / Normal`；Badge 配色 normal=灰、Invite=主题色、Owner=红。
- 权限位设计（EE）：`Read=1 / Write=2 / Manage=4 / Owner=8` 位掩码 × 11 类资源（知识库/LLM/搜索/对话/文档/画布/记忆/MCP/文件/文件夹/模型实例）；OSS 端权限助手恒返回 `false`（不禁用按钮），全部交给 EE 覆写——典型的「开源版埋接缝、企业版换实现」架构。

### 2.5 管理后台（证据：`pages/admin/`）

与用户端**完全隔离**的独立子应用：独立 URL（`/admin`）、独立登录页与凭证存储（`adminStorage` 与用户端 localStorage key 分离）、独立 API 前缀（`/api/v1/admin/*`）、独立布局；用户端没有任何指向 `/admin` 的入口。

- 布局：左侧 `w-72` 侧栏（Logo + "RAGFlow Admin" + 导航 + 版本号/主题切换/退出）+ 右侧内容区。
- 导航：服务状态 / 用户管理 / 沙箱设置（开源版）；注册白名单 / 角色 / 监控仅企业版可见（`IS_ENTERPRISE` 构建期条件注册）。
- 用户管理：TanStack Table 全功能表格（排序/过滤/分页）；状态激活开关、normal↔superuser 下拉、行 hover 才显示操作（详情/改密/删除）；**当前用户置顶且自身行不可停用/删除**（`isMe` 守卫）。
- 角色（EE）：角色 × 资源权限矩阵，`enable/read/write/share` 逐行 Switch，增量 diff 授权。
- 监控（EE）：极简——iframe 内嵌 Prometheus Alertmanager。

## 3. 用户操作流程

### 3.1 注册 → 登录

```
/login → 「Sign up」卡片翻面 → 填昵称+邮箱+密码
→ 密码客户端 RSA 加密（rsaPsw）→ POST /api/v1/users
→ 成功 toast → 卡片翻回登录面 → 登录
```

### 3.2 登录态维持

```
POST /api/v1/auth/login → 从响应头取 Authorization + body 取 access_token + userInfo
→ 三件套存 localStorage → 跳首页
→ 路由守卫以 localStorage 是否有 authorization 判断登录态（纯前端判断）
→ 登出：POST /api/v1/auth/logout → 清存储 → 硬跳 /login
```

注意：「Remember me」勾选值**采集但不发给服务端**，凭证无论勾选与否都存 localStorage——当前是纯 UI 占位。

### 3.3 危险操作反馈链（全站统一）

```
删除类操作 → ConfirmDeleteDialog（红色删除键，或 Modal.show 命令式确认）
→ 成功后 toast（顶部居中 2.5s，sonner）
```

确认弹窗两种实现并存：声明式 `ConfirmDeleteDialog`（Radix AlertDialog）与命令式 `Modal.show`（Promise 包裹 onOk）；批量操作条中 `id === 'delete'` 的项自动包确认弹窗——**全站统一的危险操作约定**。

## 4. 可借鉴的设计要点总结

1. **登录注册 3D 翻面**：一张卡片两个面，形态记忆点强、无页面跳转。
2. **Profile 概览式 + 弹窗编辑**：只读列表扫一眼即懂全貌，编辑不离开页面。
3. **头像裁剪即传即存**：canvas 输出 64×64 base64，无单独上传按钮。
4. **时区用浏览器原生 API 生成列表**：`Intl.supportedValuesOf`，零维护成本。
5. **API Key 明文 + 数量上限 + 复制绿勾反馈**：取舍是「个人工具 key 以便利优先」。
6. **权限位掩码接缝**：`ee-stub` 目录放恒真/恒假实现，EE 构建时替换——值得参考的多版本架构模式。
7. **管理后台完全隔离**：存储/API/布局三隔离，用户端零入口，缩小攻击面。
8. **自身行保护**：当前用户置顶 + 不可停用/删除的 `isMe` 守卫。
9. **危险操作单一约定**：一个组件 + 一个 id 约定覆盖全站删除确认。
