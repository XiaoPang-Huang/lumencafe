# 01 · 产品整体信息架构与页面导航结构

## 1. 功能描述

RAGFlow 是一个 RAG（检索增强生成）平台，产品对象可归纳为六类**同构资源**：知识库（Dataset）、对话应用（Chat）、搜索应用（Search）、Agent 画布（Studio）、记忆体（Memory）、技能（Skill）。所有资源共用「列表页 → 详情页」的同一套信息架构，用户只需要学会一种页面模式即可操作全部资源。

全局导航是**左侧可折叠主导航**，分三组：主导航项（6 个）→ 分隔线 → 集成中心（Integrations）→ 底部用户区（语言/主题/个人设置/退出）。

## 2. 页面布局说明

### 2.1 主导航（证据：`web/src/layouts/components/app-sidebar/`）

```
┌──────────────┬────────────────────────────┐
│ ◆ Logo       │                            │
│              │                            │
│ ⌂ Home       │                            │
│ ▣ Context    │  主内容区（Outlet）         │
│ 💬 Application│  · 列表页 = 筛选栏+网格     │
│ ✦ Studio     │  · 详情页 = 次级侧栏+内容   │
│ ▤ Library    │                            │
│ 👥 Team      │                            │
│ ──────────   │                            │
│ 🔌 Integrations                         │
│              │                            │
│ [头像] 用户名 │                            │
└──────────────┴────────────────────────────┘
```

- 折叠态宽度 `w-16`（64px），展开 `md:w-60`（240px），过渡动画 `transition-[width]`。
- 展开时 Logo（size-8）+ 企业版升级徽章；折叠时图标化（size-5）。
- 激活项高亮用「路径段边界匹配」（`matchesPath`，避免 `/chat` 误匹配 `/chat-channel`），并支持 `activeAliases`——详情页路由（如 `/dataset/*`）让父级导航项保持高亮。
- 证据：`navigation.ts`（NavItems / IntegrationChildren / PageTabGroups）、`index.tsx`（折叠逻辑）、`use-sidebar-collapse.tsx`。

### 2.2 导航项定义（证据：`navigation.ts` L41-148）

| 导航项 | 图标 | 目标路由 | 别名高亮（activeAliases） |
|---|---|---|---|
| Home | LucideHome | `/` | — |
| Context | LucideBoxes | `/datasets` | `/dataset/*`、`/memories`、`/memory` |
| Application | LucideMessagesSquare | `/chats` | `/chat/:id`、`/searches`、`/search/:id` |
| Studio | LucideSparkles | `/agents` | `/agent/*`、`/pipeline/*`、模板、日志 |
| Library | LucideLibrary | `/files` | — |
| Team | LucideUsers | `/team` | — |
| Integrations | LucidePlug | 可展开分组 | 模型/数据源/聊天渠道/MCP 四个子项 |

### 2.3 分组页签（Page-level Pill Tabs）

Context 与 Application 两个导航组在列表页顶部提供**胶囊页签**（证据：`navigation.ts` PageTabGroups、`layouts/components/nav-group-tabs.tsx`）：

- Context 组：`Dataset` | `Memories`
- Application 组：`Chat` | `Search`

即主导航只记「组」，组内资源用页签切换，不消耗导航位。

### 2.4 列表页统一骨架（证据：`components/list-filter-bar`、`card-container`、`empty/empty.tsx`）

所有列表页（datasets/agents/memories/searches/skills）同构：

```
┌──────────────────────────────────────────┐
│ 标题+icon │ ⛛筛选(带计数) │ 🔍搜索 │ [+新建] │
├──────────────────────────────────────────┤
│ [卡片] [卡片] [卡片] [卡片]               │  ← 响应式网格
│ [卡片] [卡片] [卡片] [卡片]               │     sm:1 → 2xl:5 列
├──────────────────────────────────────────┤
│                ‹ 1 2 3 ›                  │
└──────────────────────────────────────────┘
```

- 筛选按钮带**计数徽标**：有激活筛选项时从 icon 尺寸变为 default 尺寸并显示数量徽标（`bg-text-badge`）。
- 网格断点：`sm:1 md:2 lg:3 xl:4 2xl:5`，`content-start` 防拉伸。
- 空态：`EmptyAppCard`（480px 虚线卡片 = 可点击创建入口）；搜索无结果切换 `isSearch` 版（不可点击）。空态类型注册表覆盖 Agent/Dataset/Chat/Search/Memory/Skills 六类。

### 2.5 详情页「次级侧栏 + 页签」模式

详情页不用顶部 Tabs，而是左侧窄次级侧栏（证据：`pages/dataset/sidebar/index.tsx`、`pages/memory/sidebar/index.tsx`）：

- 知识库详情五个页签：文件 / 检索测试 / 概览（日志）/ 配置 / Artifacts。
- 记忆详情两个页签：Messages / Configuration。
- 次级侧栏可折叠，且**与主导航折叠联动**（双级侧栏联动，`pages/dataset/index.tsx` L31-40）。

## 3. 用户操作流程（典型）

```
登录 → 主导航选 Context → 页签选 Dataset
     → 列表页点空态卡（或「+新建」）→ 创建对话框
     → 进入详情页（主导航自动折叠）→ 次级侧栏页签操作
     → 返回列表（主导航展开恢复）

登录 → 主导航选 Application → 页签选 Chat
     → Chat 应用卡片 → 进入对话页（含会话侧栏）
```

点击资源卡片进入详情时，**主导航自动折叠**为详情页侧栏腾空间，返回时恢复——空间利用的细颗粒联动。

## 4. 可借鉴的设计要点总结

1. **资源同构 = 学习成本归零**：六类资源一个卡片组件（`HomeCard`）、一套列表骨架；差异通过 props（moreDropdown/sharedBadge/extra）注入。
2. **空态即入口**：空卡片本身就是创建按钮，且支持 URL `?isCreate=true` 深链直达创建弹窗。
3. **导航三件套**：主导航记组、页签切资源、别名保高亮——避免导航项爆炸。
4. **计数徽标反馈**：筛选激活状态用按钮形态变化 + 数字徽标表达，不占额外空间。
5. **详情页双级侧栏联动**：进入沉浸操作自动腾空间，退出恢复。
6. **路径段边界匹配**：高亮逻辑按段匹配，杜绝前缀误亮。
