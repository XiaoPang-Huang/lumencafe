## 背景

DeepSeek Harness 团队 2026-10-31 发布 Super-agent 设计探索文章，2026-11-01 做了系统性研究：
原文五模块原理 → 六层框架整理 → 对本应用逐模块对账（23 项：已有 3、部分 9、缺 9、不需要 2）→ 出增量架构与 R1-R7 改造清单。
该方案目标是常驻 Router + 隔离 Worker 的完整 Agent 底座（新增 8 张 `agent_*` 表、`agent-worker` 容器）。

## 核心结论

### 六层框架 / 七维考量

- 六层：交互层（多信道）→ 事件层（Trigger 两级过滤）→ 路由层（Router 只分派不执行）→ 执行层（Worker 上下文隔离）→ 状态与环境层（状态入库、环境留原地）→ 守护层（Watchdog 外部控制回路）。
- 四特征（连续/高效/主动/持久）由五模块共同支撑，单个 ReAct Loop 撑不起。
- 七维考量：边界情况、异常处理、性能与扩展性、状态管理、安全与权限、可观测性、失败恢复——每维均给出原文对策 + 本项目需自行设计的【判断】项。

### R1-R7 改造清单

- R1 任务事件表与链式编排：关键状态变化写事件，Hatchet 按事件链接任务（P0，论文域收益最直接）。
- R2 Watchdog 守护清扫：定时扫描超时任务，自动重试一次后标 failed 写原因，不做 LLM 会话式版（P0）。
- R3 事件注入防线：外部文本进提示词前消毒 + 隔离包装，声明「数据不等于指令」（P1）。
- R4 任务状态机与可恢复规范：统一 pending/running/done/failed 四态与幂等重放语义（P1）。
- R5 digest 两级过滤精化：确定性关键词为 Fast Path，LLM 只复核候选（P2）。
- R6 高相关论文投机预解析：自动预下载预解析、失败静默（P2，待成本拍板）。
- R7 长对话上下文压缩：旧消息压摘要（Spill）、近期保原文（Inline），替代直接丢弃（P2）。

## 不采纳原因

- 两人自用规模裁剪：Router/Worker 双层、Router 批处理、多信道交互、BYOM/端侧 daemon、LLM 会话式 Watchdog 全部不采纳；全双工异步工具暂缓（原 4.9 节不采纳清单）。
- 2026-11-06 决策改走 Pi 选型路线，完整 Agent 底座（8 表 + agent-worker）不再建设，本文档所含设计随路线一并废弃。

## 遗留有效教训

- 工具粒度决定智能上限：工具契约（十项字段、副作用、幂等、超时）比提示词更能约束行为。
- 状态必须落库：计算无状态、状态入库，进程重启等价于热启动，重启后可从库恢复全部上下文。
- 沙箱隔离两条通道：外部文本进提示词前消毒隔离（数据不等于指令）；凭据最小权限、掩码展示、不接触即可用。
