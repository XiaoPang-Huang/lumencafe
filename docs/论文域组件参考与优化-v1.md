# 论文域组件参考与优化 v1（2026-10-25）

> 覆盖论文域路线图四件事：推送 / 预览 / 笔记 / 问答；外加解析（MinerU API）与 embedding 选型。
> 口径照旧《组件选型》三层模型 + 许可证红线（《组件选型》§九.7）。代码与前端优化见 §六、§七。

## 〇、结论先放

1. **你的三个技术设想（MinerU API 解析、LLM API 问答、embedding API）方向都对。** 最重要的补充：问答和 embedding **都走自家网关**，别直连厂商——模型管理「纯网关」的决策正好覆盖它们。
2. **最值钱的两个借鉴模式**（来自 Elicit/SciSpace/Semantic Scholar 的做法）：
   - 一份解析三处复用：预览、RAG、笔记锚点，全用 MinerU 同一份结构化产物；
   - 答案引用可点击跳原文：问答每条结论带来源，点了跳到 PDF/段落高亮。
3. **代码层先做 3 件事**：APScheduler 落地（推送的前置）、网关加 embeddings 转发、解析任务表。
4. **前端：论文域就是「真前端」的立项触发点。** 原型阶段的四项缓行结论维持（见《前端现代化体检-第三档评估-v1.md》）。
5. **产品澄清（2026-10-25）：文献不限行业，推送按用户自己的配置走。** 好消息是订阅地基已在（用户级 `subscribe_keywords`）；真正的行业锁定在**数据源**（PubMed 只覆盖生物医学）和硬编码打标规则，见 §二。

## 一、解析：接 MinerU API，可行且划算

事实（2026-10 核实，接入前以官方文档为准）：

| 通道 | 能力 | 限制 |
|---|---|---|
| Agent 轻量 API | 免登录，回 Markdown | 单文件 10MB / 20 页，IP 限流 |
| 精确解析 API | token 认证，Markdown+JSON（带版面位置） | 200MB / 600 页，可批 200 文件 |

- **免费额度**：官方 API 每日约 1000 页高优先额度，额度内不按次收费，超量降级处理不扣钱。论文场景（每天几十篇）基本免费。
- 限流约：提交 300/分、查询 1000/分、1 万文件/天。
- **许可证红利**：走 API 网络调用 = 不嵌入代码 = 许可证传染问题消失（MinerU 3.1.0 起是自定义许可，嵌入要小心，API 调用不用）。在线服务需署名 MinerU。
- **坑**：官方文档自己警告——GitHub/AWS 等境外 URL 可能抓取超时。做法：**后端先下载 PDF，再把文件传给 MinerU**，别让它去抓 URL。

**实现模式：一份解析三处复用。** MinerU 输出的是带版面位置的结构化文档（Markdown/JSON/Content List，含引用定位）：

1. 预览：Markdown 直接渲染（轻预览）；
2. 问答：切成 chunk 入库时**带上页码/位置元数据**——这是引用溯源的地基；
3. 笔记：锚点挂在 chunk/位置上，点引用跳原文。

解析结果**存数据库**（不是只存文件），见 §六表设计。

备选通道（MinerU 不可用时）：Docling 自托管（MIT，CPU 可跑）；**Grobid**（学术文献老牌解析器，Elicit 就用它解析全文，引文头部解析强）；RAGFlow（《组件选型》§二，重）。

## 二、订阅与推送（用户配置驱动，不限行业）

**现状地基已经在**：抓取按「用户级订阅关键词」聚合——每个用户自己的 `subscribe_keywords`（`user_settings` 表，`papers_crawl.py:204` 的 collect_keywords 聚合），没配置的用户回落 env 默认关键词。「根据用户配置推送」不用新建机制，是把这层用起来。

产品澄清后有两处行业锁定要拆：

1. **数据源锁定（大头）**：现在只接 NCBI PubMed（`papers_crawl.py:29`）——它只覆盖生物医学。用户要订阅工程、计算机、经济、教育等任意行业，PubMed 根本没有。跨行业方案：
   - **OpenAlex API**（免费、无密钥、全学科 3 亿+ 作品）→ 跨行业首选补充源；
   - **Semantic Scholar API**（免费、全学科，顺带 TLDR/引用数，与 §五引文图谱共用）；
   - arXiv API（CS/物理预印本，按需）；
   - 接入方式做成 **Source Provider 抽象**（学 `skillhub.py` 的协议冻结模式：先 PubMed 一个实现，加源不改管线）。
2. **打标规则锁定（小头）**：`TAG_RULES`（`papers_crawl.py:36`）是旧项目的神经科学硬编码（AD/PD/ALS）→ 泛化为「LLM 按用户关键词打标」或干脆标签来自用户配置，别写死行业词。

**推送组件与模式**：

- 组件：**ntfy**（自托管推送，几十 MB，手机 App 收）→ 首选；**Apprise**（库，一个接口推 70+ 渠道）→ 想推 Telegram/邮件时（《组件选型》§五）。
- 模式（学 paper digest / Zotero 订阅）：
  - 每日 digest 聚合：「今日为你命中 12 篇：3 篇高相关」，附链接；
  - 高相关才即时推（该用户关键词打分超阈值），别逐条轰炸。
- **前置依赖：APScheduler**。推送是定时任务的第一个真实用户——落地它才能开推送（见 §六）。

## 三、预览

- 组件：**PDF.js**（Mozilla，Apache-2.0）——浏览器里渲染 PDF + 文本层，业界唯一标准答案（Zotero、arXiv 预览、Semantic Scholar 都是它）。
- 两级预览：
  - 详情页轻预览：MinerU 的 Markdown 渲染，秒开、移动端友好；
  - 阅读器：PDF.js 全文 + 文本层。
- **实现模式**：文本层 + chunk 位置元数据 → 问答引用点击跳页高亮（§五 citation 的落点）。
- PDF 从哪来：PubMed 只有摘要。全文用 **Unpaywall API**（免费）查开放获取链接——Elicit 同款做法；查不到就只有摘要级问答。
- 缩略图：poppler（pdftoppm）以独立 CLI 进程调用（GPL 不嵌入，红线合规）。

## 五、问答 + Embedding

**问答架构：自研薄 RAG 管线，不引重框架。**
业界标准模式是两段式（Semantic Scholar/Elicit 都是）：粗召回（关键词 + 向量）→ 重排（reranker）→ 生成带引用。落到我们：

1. 检索：pgvector 向量召回（既定基线）+ 关键词兜底；
2. 重排：可选 bge-reranker 托管 API（SiliconFlow 等有），效果提升明显、成本低；跳过也能用；
3. 生成：走自家网关调 LLM，答案要求每条结论带 `[n]` 引用标记；
4. **citation 溯源**：`[n]` → chunk → 页码/位置 → 预览高亮。这是 Elicit「每条 claim 链接到来源」的同款体验，也是我们相对「裸聊天」的差异化。

为什么自研薄管线而不是 LlamaIndex/LangChain：我们已有 `chat_service` 的流式注入模式（skill 注入点同构），论文问答 =「带论文上下文的对话」，复用 chat SSE 管线即可，另起一套对话系统是重复建设。LlamaIndex 当参考实现读，不当依赖引。

**Embedding：走自家网关，这正是「纯网关」的用武之地。**

- 国内外 embedding API 全是 OpenAI 兼容（智谱 embedding-3、阿里 text-embedding-v4、SiliconFlow BGE-M3、OpenAI text-embedding-3）→ `llm_gateway` 加一个 `/v1/embeddings` 转发就通（它本来就是「OpenAI 兼容统一出口」，`llm_gateway.py:1-14`）。
- 模型管理：`llm_models` 表加 embedding 模型标记（如 `modality` 列），默认路由复用现有两标记机制——不加应用绑定，符合架构定稿。
- 存储：pgvector。**一个要提前定的事**：换 embedding 模型 = 全量重嵌入（维度还可能变），模型选定后别频繁换。
- 不自建 embedding 服务（VPS 无 GPU，BGE 本地跑不动）。

**加分项：引文图谱与元数据（API 外采，脏活典型）。**
Semantic Scholar API / OpenAlex API（都免费）：引用数、TLDR 摘要、相关文献推荐——Elicit 的「引文图谱探索」模式。自爬引用图谱是找死，API 直取值回票价。**这两个 API 与 §二的跨行业数据源是同一批**，加源时一并接。放二期。

## 八、实现详述（表设计草稿与数据流）

> 动工时按本节落地；DDL 走 Alembic 0003，只增不改旧。

### 8.1 解析链路完整数据流（MinerU 接入六步）

1. 入队：详情页点「解析全文」→ 建 `papers_parse_jobs` 行（status=pending）。
2. 取 PDF：Unpaywall 查 OA 链接 → 后端下载落盘 `data/papers/pdf/`；境外源超时换源或标失败（§一的坑）。
3. 调 MinerU：上传文件到精确解析 API，拿 `task_id` 走异步模式，不阻塞等。
4. 轮询：APScheduler 每分钟扫 pending/running 查状态（MinerU 查询限流 1000/分，余量足）。
5. 落库：Markdown 存 `papers.markdown`（轻预览直接用）；切 chunk 存 `paper_chunks`，每条带 page/position（引用溯源地基）。
6. 向量化：chunk 文本走网关 `/v1/embeddings` 批量转，向量存 pgvector。

失败兜底：重试 3 次标 failed 记 error；每日额度（约 1000 页）用尽则排队到次日。

### 8.2 表设计草稿

**papers_parse_jobs**（MinerU 异步任务状态机）

- id / paper_id FK / status（pending | running | succeeded | failed）
- mineru_task_id / error / page_count
- created_at / finished_at

**paper_chunks**（chunk 文本 + 向量 + 位置）

- id / paper_id FK / seq（切块序号）
- text / page / position JSONB（MinerU 版面坐标）
- embedding vector(1024)（BGE-M3 维度；换模型需全量重嵌入，§五）
- 索引：HNSW(embedding) + btree(paper_id, seq)

**既有表补列**（只增不改旧）

- `papers` +：pdf_url / pdf_path / fulltext_status（none | parsing | ready | failed）/ markdown TEXT
- `PaperNote` +：anchor JSONB（chunk_id / page，可空，旧笔记不受影响）

### 8.3 网关 embeddings 转发（改动集中一个文件）

- `llm_gateway.py` 加 `POST /v1/embeddings` 透传：请求体转给默认 embedding 模型的 base_url，Key 服务端查库注入、零回显——与 chat 转发同一套规矩（`routers/gateway.py:4` 零 Key 原则同源）。
- `llm_models` 加 `modality` 列（chat | embedding），默认路由复用 `is_default` 两标记机制，不加应用绑定（架构定稿）。
- 管理界面「模型管理」按 modality 分组；界面对照 one-api / Open WebUI 案例（设计强制规则）。

### 8.4 问答管线六步（复用 chat SSE，不另起对话系统）

1. 召回：关键词 + pgvector 双路取 top-k chunk（多篇论文时先按当前论文/收藏过滤）。
2. 重排（可选）：bge-reranker API 把 top-20 压到 top-5，跳过也能用。
3. 组装：chunk 文本 + 编号注入上下文——走 `chat_service` 的 skill 注入点同构位，不动对话系统。
4. 生成：网关流式出，要求结论带 `[n]` 引用标记。
5. 后处理：解析 `[n]` → chunk_id → 返回结构化 citation 数组。
6. 前端：点 `[n]` → PDF.js 跳页 + position 坐标高亮。

### 8.5 digest 推送数据流

1. APScheduler 每日定时（用户可配时间），对每个配了订阅关键词的用户跑一遍。
2. 打分：新命中论文按关键词相关度打分，超阈值归「高相关」。
3. 聚合渲染：「今日命中 12 篇（3 篇高相关）」+ 链接列表。
4. 出口：ntfy 主题推手机；要 Telegram/邮件时换 Apprise（同一接口）。
5. 即时推：高相关单条即时推，不等 digest（§二的防轰炸原则）。

### 8.6 组件速查表

| 组件 | 接入方式 | 角色 |
|---|---|---|
| MinerU API | 网络调用 | PDF → 结构化 Markdown/JSON（解析主通道） |

| CodeMirror 6 / Vditor | 库（MIT） | 笔记 Markdown 编辑（二选一） |
