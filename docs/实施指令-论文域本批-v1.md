## 步 A：数据源扩展 + AI 生成关键词

**目标**：用户可勾选 arXiv/OpenAlex/S2/DOAJ（PubMed 收编为 provider 之一），抓取按人按源聚合；一句话生成订阅关键词。

**后端**：
1. `app/services/sources/`（契约冻结，学 `skillhub.py` 模式）：
   - `base.py`：SourceProvider 抽象（`name` / `display_name` / `search(keywords, since_date) -> list[PaperItem]`，PaperItem 统一字段：title/authors/abstract/year/doi/arxiv_id/url/source）
   - `arxiv.py` / `openalex.py` / `semantic_scholar.py` / `doaj.py` 四个新源；`pubmed.py` 把 papers_crawl.py 现有 esearch/efetch 逻辑收编（逻辑搬家不改语义）；全部走共享 httpx 总机 + tenacity 重试（步 2 三小件已就位）
2. `user_settings.subscribe_sources`（JSONB 数组，如 `["pubmed","arxiv","openalex"]`；未设置 = 默认 `["pubmed","arxiv","openalex"]`）；`papers_crawl.py` 改造：对每个开了文献权限的用户，按其勾选源 × 其关键词分别抓取 → 按 doi/arxiv_id 去重 → 沿用现有 upsert/打标入库
3. `GET /papers/sources`：已注册源清单（key/名称），给前端勾选框用
4. `POST /papers/suggest-keywords`：入参 `{description}` → 走网关 `chat_once`（app_key=`papers_config`，未配置回落默认路由，系统提示词内置：把用户大白话扩成 8-12 个检索关键词、中英都给出、严格 JSON 返回）→ 返回关键词数组；**不写库**（保存走用户设置接口）

**测试**：四源各 1 例（mock HTTP 响应，学现有 test_papers 模式）；跨源去重；按用户源聚合（A 勾 arXiv、B 勾 PubMed 互不影响）；suggest-keywords（mock LLM 返回固定 JSON）；回归全绿。

**验收**：手动触发抓取，库里出现 arXiv/OpenAlex 新论文（source 字段正确）；suggest-keywords 实测返回中英文关键词。
**commit**：`feat(论文域): 数据源多源扩展（arXiv/OpenAlex/S2/DOAJ）+ AI 生成订阅关键词`

## 步 B：页内 digest + Hatchet 落地

**目标**：「今日命中」按人打分聚合可查询；「立即检索」接口；Hatchet 定时每日自动跑。

**后端**：
1. 新表 `papers_crawl_runs`（Alembic 0006，只增）：run_at / trigger（schedule|manual）/ 各源命中数 JSONB / status——支撑页面「已更新于 HH:MM」
2. `GET /papers/digest`：当前用户今日命中（papers 按抓取日过滤 × 个人关键词打标）+ 高相关标记（打标分 ≥ 阈值，阈值常量先简单后精细）+ last_run 时间
3. `POST /papers/crawl-now`（登录用户可触发，防并发锁）→ 同步跑一轮抓取写 runs 表 → 返回命中摘要
4. **Hatchet（lite 形态）**：compose +1 容器 `hatchet`（`hatchet-lite` 镜像，锁版本+digest；`DATABASE_URL` 指现有 PG 的 **hatchet 独立库**——部署时 `CREATE DATABASE hatchet` + `CREATE EXTENSION btree_gist`；设容器内存上限 512M）；Caddy `/admin/hatchet` 子路径反代控制台（D7/D8 既定）；后端加 `hatchet-sdk`（锁哈希）；注册每日 cron workflow（早 7:30）调抓取服务同一函数；`/internal` 健康检查接线
5. 引擎/控制台初始账号密码进 `.env`，文档写明

**测试**：digest 聚合（多用户隔离、高相关阈值边界）；crawl-now 幂等/并发锁；runs 表写入；回归全绿。Hatchet 连通性冒烟：手动触发一次 workflow 成功、控制台可登录。

**验收**：定时到点自动跑（注入时钟或缩短 cron 实测）；页面数据口径与库一致。
**commit**：`feat(论文域): 页内digest（今日命中+高相关）+ Hatchet定时引擎落地（第一条流水线）`

## 步 C：前端骨架重排 + 暗色模式

**目标**：论文页按认可线框重排；订阅设置弹窗；暗色双主题。

**前端**（app.js / main.css，事件委托，bump `?v=`）：
1. 论文页三栏骨架：顶栏（今日命中 N 篇 + 高相关红标 + 更新时间 + 立即检索按钮 + ⚙订阅设置）/ 左导航（今日推送/我的收藏/全部论文，笔记占位）/ 中间卡片流（标题/来源徽标/相关度/摘要两行/操作行：收藏/下载占位/解读）/ 右侧详情面板（摘要+元数据）
2. 订阅设置中央弹窗：关键词编辑（标签式增删）+「AI 生成」区（输入大白话→生成→点选追加）+ 数据源勾选（GET /papers/sources）；保存走用户设置接口
3. **暗色模式**：CSS 变量双主题（`[data-theme=dark]` 全量变量映射，参考对象 Open WebUI/Arco dark），「我的→通用设置」加主题切换（跟随系统/浅色/深色），默认跟随系统；改完逐页目检（本批范围：外壳+工作台+论文页+管理页）
4. 手机端折叠单栏（导航→列表→详情逐级）

**验收**：playwright 走查（digest 展示/立即检索 loading→刷新/订阅弹窗全流程/暗色切换全页目检截图）；回归其他页无 JS 报错。
**commit**：`feat(论文域): 论文页三栏骨架+订阅设置弹窗 + 暗色模式双主题`

## 步 D：COS 存储抽象层

**目标**：接 COS SDK，封装存储抽象；**强制按应用隔离目录**（P11 硬性规定）；下载按钮不做（下批）。

**后端**：
1. `cos-python-sdk-v5` 入 requirements（锁哈希）+《依赖锁定清单》入册
2. `app/services/storage.py`：抽象接口 `put(app, key, data)` / `get(app, key)` / `delete(app, key)` / `exists(app, key)`；**app 前缀硬约束：key 一律 `{app}/...` 形式，传入即校验，跨应用路径直接 raise**（P11）
3. 两个实现：COS（凭证从 service_keys 取 `tencent_cos_id`/`tencent_cos_key`，endpoint 取 `tencent_cos_key` 行的网址字段；凭证缺失时**明确报错**不静默）+ Local（data/<app>/ 目录，开发兜底）
4. 连通性自测：容器内对 `papers/_selftest.txt` 上传→下载→删除一遍（用 pytest 或一次性命令），通过即接线完成；本期不接任何 UI

**测试**：前缀校验（非法路径拒绝）；Local 实现全操作；COS 实现 mock（不真连）；凭证缺失报错路径。
**commit**：`feat(底座): COS存储抽象层（按应用目录硬隔离）+ 本地兜底实现`
