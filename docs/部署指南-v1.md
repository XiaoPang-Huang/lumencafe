# 部署指南 v1（云服务器）

> 结论先行：一台 2核4G 的 VPS 足够。全栈 Docker Compose 四件套（PostgreSQL / FastAPI / Caddy），**IP 直连模式**：Caddy 同源反代 + 自签证书，不用域名、不碰备案。三步：装 Docker → 传代码 → 一条 compose 命令。预计 30 分钟。

## 0. 服务器要求

- 配置：2 核 4G 内存、20G 磁盘起步；系统 Ubuntu 22.04 / 24.04 LTS
- 防火墙放行：22（SSH）、80、443、8443（主站；Kuma 监控台已按 v2.8 拆除，8444 不再需要）
- 5432（PostgreSQL）、8000（API）**不要**暴露公网，compose 内部走服务名互通
- SSH 建议改用密钥登录，禁用密码登录

## 1. IP 直连（不需要域名）

域名未备案会被腾讯云拦截 80/443（详见 §1.1），所以本项目默认**全程 IP 直连**，不申请、不配置任何域名：

| 地址 | 用途 |
|---|---|
| `https://<服务器IP>:8443` | 主站（前端 + /api 同源反代），自签证书 |
| `https://<服务器IP>` | 主站备用地址（若腾讯云不拦 IP 直连的 443，先试这个） |
| `http://<服务器IP>` | 80 端口，自动跳 `https://<IP>:8443` |

首次打开主站会提示「证书不受信任」：点 高级 → 继续访问。自签证书加密有效，只是没有 CA 背书。

### 1.1 备案提醒（重要，先读）

**境内云服务器（腾讯云/阿里云等）会拦截未备案域名的 80 和 443 端口**——公网访问连接被重置，Let's Encrypt 无法完成验证，Caddy 日志报 `Connection reset by peer`。

这里有两个独立的坑，别混为一谈：

1. **访客进不来**：80/443 被拦 → 站点改用 8443 端口提供服务，访客地址带端口
2. **证书签不了**：Let's Encrypt 只在 80（HTTP-01）和 443（TLS-ALPN-01）验证，站点换到 8443 也救不了证书 → 要么走 **DNS-01**（经 DNSPod API 加 TXT 记录验证），要么**放弃域名改用 IP 直连**

#### 当前模式：IP 直连（2026-10-18 起启用）

未备案域名短期无解，而 IP 地址不携带域名信息、不在拦截范围内，所以先用 IP 跑通：

- 访问：`https://134.175.114.81:8443`（保底）；若腾讯云不拦 IP 直连的 443，`https://134.175.114.81` 也可用（待实测）
- 证书：Caddy 内部 CA 自签（`tls internal` + `on_demand`，IP 无 SNI 也能握手，已实测）。加密有效，但浏览器提示「不受信任」，需点一次「高级 → 继续访问」
- 零凭证、零 DNS、零自定义镜像，官方 caddy 镜像即可

Caddyfile 里 443/8443 双端口监听、内容相同，哪个不被拦截就用哪个；80 端口统一跳 8443。

#### 升级路径 A：域名 + DNS-01（无需备案，浏览器绿标）

四处联动（`deploy/Caddyfile.domain` 是备好的域名版配置）：

1. `cp deploy/Caddyfile.domain Caddyfile`
2. `docker-compose.yml` 的 caddy 恢复 `build: ./deploy/caddy`（带 DNSPod 插件的自定义镜像）
3. `.env` 配 `DNSPOD_TOKEN`（DNSPod 控制台 → 用户中心 → API 令牌 → 创建，格式「ID,Key」）
4. `docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build`

原理：LE 只在 80/443 验证，换端口救不了证书；DNS-01 通过 DNSPod API 自动加 `_acme-challenge` TXT 记录完成验证，完全不依赖入站端口，自动续期。

#### 升级路径 B：ICP 备案（约 2–3 周）

通过后删掉域名版 Caddyfile 各处 `:8443`、`(dns_tls)` 片段和 `import dns_tls`，compose 的 caddy 改回 `image: caddy:2-alpine`，删 `deploy/caddy/` 和 `.env` 的 `DNSPOD_TOKEN`，然后 `up -d --build`。以前备过案（有备案号）可走「接入备案」，快很多。

#### 排查方法

在服务器上执行，别用自己电脑探测（本机代理软件会骗你）：

```bash
curl -ks https://127.0.0.1:8443/api/health   # 服务器本地通 → 服务没问题，是被拦在公网入口
docker logs lumencafe-caddy-1 --tail 30      # 看错误详情
```

日志里出现 `43.174.x.x`（腾讯云 IP）的 `reader size limit exceeded` 或 `Connection reset by peer`，就是被拦截的实锤。

## 4. 改 .env（关键项，缺一不可）

| 项 | 怎么填 |
|---|---|
| LUMEN_JWT_SECRET | `openssl rand -hex 32` 生成，必须改 |
| POSTGRES_PASSWORD | 强密码；含 `$` `#` 时值用单引号包住 |
| LUMEN_DATABASE_URL | 密码部分做 URL 编码（@→%40、#→%23、$→%24） |
| LUMEN_INTERNAL_TOKEN | `openssl rand -hex 32` |
| DNSPOD_TOKEN | 仅域名模式（DNS-01）需要；IP 模式留空，见 §1.1 |
| HATCHET_ADMIN_EMAIL / HATCHET_ADMIN_PASSWORD | Hatchet 控制台初始管理员（论文域步 B）；生产必须改，密码 8-64 位含大小写+数字 |
| HATCHET_CLIENT_TOKEN | Hatchet worker 接入令牌（§7 生成；留空 = 不接线，定时抓取退化 /internal/jobs） |
| HATCHET_SERVER_URL | 引擎对外 URL：IP 直连填 `https://<IP>:8443/admin/hatchet` |
| HATCHET_COOKIE_DOMAIN | 会话 cookie 域：填服务器 IP（经该 IP 访问控制台才带得上 cookie） |

LUMEN_CORS_ORIGINS 生产同源访问，留空即可。

## 5. 改域名（仅域名模式需要；IP 直连模式跳过本节）

> 当前默认是 IP 直连模式（根目录 Caddyfile 为 `:443, :8443` 通配站点，无需改域名）。
> 只有切到域名模式（§1.1 升级路径 A）时才需要本节。

编辑根目录 `Caddyfile`（或从 `deploy/Caddyfile.domain` 复制），把 `cafe.lumenhub.online`、`api.lumenhub.online` 换成你的域名。注意域名后面带 `:8443`（未备案方案，见 §1.1），换域名时连同端口一起改，且**别删 `import dns_tls` 行**（DNS-01 签证书用）。Caddy 会自动申请并续期 Let's Encrypt 证书。

## 6. 启动

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build
```

启动过程自动完成：跑 Alembic 迁移 → 播种种子数据（含 admin 账号）。首次访问 `https://134.175.114.81:8443` 登录后**立刻改 admin 密码**（.env 里初始值是 `change-me-too`）。

验证（IP 直连模式，`-k` 忽略自签证书告警；注意健康检查在 `/api/health`——Caddy 只反代 `/api/*`，`/health` 会落到前端文件服务器返回空 404）：

```bash
curl -k https://134.175.114.81:8443/api/health                       # {"status":"ok"}
curl -ks -o /dev/null -w '%{http_code}\n' https://134.175.114.81:8443/internal/jobs/papers-crawl   # 必须输出 404（内网专用；空 body 看不到状态码，故用 -w）
```

## 7. Hatchet 定时引擎（论文域步 B；lite 单容器，随 compose 自动起）

引擎容器 `hatchet` 随 compose 自动启动（复用现有 PG 的独立库 `hatchet`，控制台
经 Caddy `/admin/hatchet` 子路径反代，不公网暴露其他端口）。**首次部署需一次性
建库**（引擎迁移自建表与 btree_gist 扩展，勿手工预建扩展——迁移内
`CREATE EXTENSION` 非幂等，预建会导致迁移失败）：

```bash
docker exec $(docker ps -qf name=-db-) psql -U lumencafe -d postgres \
  -c "CREATE DATABASE hatchet" \
  -c "ALTER DATABASE hatchet SET TIMEZONE='UTC'"   # 引擎强制 UTC 时区校验
```

worker 接入令牌（后端 api 容器里的 SDK worker 连引擎 gRPC 用；token 有效期 90 天，
到期轮换重填）：

```bash
docker exec $(docker ps -qf name=-hatchet-) /hatchet-admin token create \
  --config ./config --name lumencafe-worker
# 输出填到 .env 的 HATCHET_CLIENT_TOKEN，然后 docker compose up -d api
```

- 控制台：`https://<IP>:8443/admin/hatchet`（仅管理员；初始账号 = .env 的
  `HATCHET_ADMIN_EMAIL` / `HATCHET_ADMIN_PASSWORD`，**首登后立刻改**）。
- 定时任务：每日 7:30（Asia/Shanghai）自动跑一轮文献抓取；到点看
  `papers_crawl_runs` 表或控制台 Runs 页验证。
- `HATCHET_CLIENT_TOKEN` 留空也可运行：后端启动时跳过接线（日志有 info），
  定时抓取退化到 `POST /internal/jobs/papers-crawl`（内部令牌触发，Q11 同日幂等）。

```bash
docker compose logs -f api

```

### 备份与恢复（restic，底座步 4）

备份服务随 compose 自动起：每 24h 把 `pg_dump -Fc` + `./skills` 加密备份到宿主机
异目录（`.env` 的 `BACKUP_REPO_HOST_PATH`，默认 `./backups/restic`），保留
日备 7 份 + 周备 4 份自动清理。口令 = `.env` 的 `RESTIC_PASSWORD`，**丢失即不可恢复**。

```bash
# 手动跑一轮（调试验收）
docker compose run --rm backup --once

# 看快照 / 仓库状态
docker compose exec backup restic snapshots
docker compose exec backup restic stats

# 最近一轮备份结果（工作台「备份」状态灯同一份数据）
docker compose exec api cat /var/lib/backup-state/last_run.json
```

恢复到新库（演练/灾备；本机 Git Bash 执行需加 `MSYS_NO_PATHCONV=1`，否则 / 开头的
参数会被 Git 转成 Windows 路径）：

```bash
# 1) 恢复快照到宿主机目录（./backups/restore-test 为任意空目录）
MSYS_NO_PATHCONV=1 docker compose run --rm --entrypoint restic \
  -v ./backups/restore-test:/restore backup restore latest --target /restore
# 2) 建临时库并导入（dump 文件在 /restore/tmp/*/db.dump）
docker exec lumencafe-db-1 psql -U lumencafe -c "CREATE DATABASE restore_check;"
cat <恢复出的 db.dump 路径> | docker exec -i lumencafe-db-1 pg_restore \
  -U lumencafe -d restore_check --no-owner --no-privileges
# 3) 核对行数后清理
docker exec lumencafe-db-1 psql -U lumencafe -c "DROP DATABASE restore_check;"
```

要彻底迁库：停 api → 把临时库改名替换 lumencafe（或 pg_dump 导出再导入），起 api。
升级 restic / postgres 镜像前按《依赖锁定清单》D13 流程评估（`deploy/backup/Dockerfile`）。

## 没有域名怎么办

**不需要域名——IP 直连就是当前模式**（见 §1 和 §1.1）。如果连公网 IP 都不想暴露，把防火墙收成只放行 22，然后用 SSH 端口转发本地访问：

```bash
ssh -L 8443:127.0.0.1:8443 ubuntu@<服务器IP>
# 然后本地浏览器开 https://127.0.0.1:8443
```

## 附录 · 从本地上云一步一步（原《从本地上云 v1》，2026-10-25 并入）

> 结论：**不必须先传 GitHub，但强烈建议走 GitHub**。你的仓库远程已经建好（`github.com/XiaoPang-Huang/lumencafe`），本地有 15 个提交没推上去。走 GitHub 以后每次更新就是服务器上一条 `git pull`；不走，以后每改一行代码都要重新打包上传，还容易漏文件。

## 路线 A：GitHub 中转（推荐）

### 第 1 步：推送到 GitHub

在本机项目目录执行：

```bash
git status          # 确认干净（没有未提交改动）
git push            # 把 15 个提交推上去
```

注意：**本机现在的网络代理拦着 GitHub**（连 github.com:443 失败）。推送要在能访问 GitHub 的网络下做——家用宽带、手机热点都可以；公司内网可能要关代理或换网。

第一次推送可能遇到两种情况：

| 情况 | 原因 | 怎么办 |
|---|---|---|
| 要输账号密码 | GitHub 2021 年起禁用了密码 | 密码栏粘贴 Personal Access Token（见下方申请） |
| 远程仓库非空被拒 | 建仓库时勾了「Add README」 | `git pull --rebase origin main` 后再 push |

申请 Token：GitHub 网页 → 右上头像 → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token → 勾 `repo` 权限 → 复制保存（只显示一次）。

### 第 2 步：准备服务器

还没有服务器就先买：2 核 4G、Ubuntu 22.04，阿里云 / 腾讯云轻量应用服务器即可（约 60-100 元/年档位）。

控制台里做两件事：

1. 安全组 / 防火墙放行：22（SSH）、80、443
2. 记下公网 IP

### 第 3 步：SSH 连上服务器

本机终端执行（Windows 用 PowerShell 或 Git Bash）：

```bash
ssh root@你的服务器IP
```

第一次连接问 `yes/no`，输 `yes`。 root 密码在服务器控制台能看到（买的时候设的或重置的）。

### 第 4 步：服务器装 Docker

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
docker --version
```

### 第 5 步：克隆代码（私有仓库要认证）

推荐配 SSH 密钥，一次配好以后免密：

```bash
ssh-keygen -t ed25519          # 一路回车
cat ~/.ssh/id_ed25519.pub      # 复制输出的公钥
```

然后浏览器打开你的仓库 → Settings → Deploy keys → Add deploy key → 粘贴公钥 → 保存。

回到服务器：

```bash
git clone git@github.com:XiaoPang-Huang/lumencafe.git
cd lumencafe
```

图省事的替代方案（Token 会留在命令历史里，介意就用上面的）：

```bash
git clone https://<你的TOKEN>@github.com/XiaoPang-Huang/lumencafe.git
```

### 第 6 步：改配置

```bash
cp .env.example .env
openssl rand -hex 32          # 生成一个，填到 LUMEN_JWT_SECRET
```

编辑 `.env`，必改三项：

| 项 | 改成什么 |
|---|---|
| `LUMEN_JWT_SECRET` | 刚才生成的长随机串 |
| `POSTGRES_PASSWORD` | 强密码（含 `$` `#` 就用单引号包住值） |
| `LUMEN_INTERNAL_TOKEN` | 再 `openssl rand -hex 32` 生成一个 |

**不用改 Caddyfile**：当前是 IP 直连模式（域名未备案被腾讯云拦截 80/443，全程 IP），
Caddyfile 里的站点是 `:443, :8443` 通配形式，不绑定任何域名。想要域名绿标再切
`deploy/Caddyfile.domain`（DNS-01，见部署指南 §1.1）。

### 第 7 步：启动

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build
```

等 2-3 分钟（要拉镜像、编译、跑迁移）。验证：

```bash
curl -k https://<服务器IP>:8443/api/health
```

返回 `{"status":"ok"` 就成了（注意是 `/api/health`，Caddy 只反代 `/api/*` 前缀）。浏览器打开 `https://<服务器IP>:8443` 登录，账号 `admin`，初始密码在 `.env` 里（`change-me-too`）——**第一时间改掉**。

## 路线 B：不经过 GitHub，直接上传

适合：只想一次性跑起来看看，不在乎以后更新。

服务器装 Docker（同第 4 步）后，本机执行：

```bash
scp -r /e/Projects/lumencafe root@服务器IP:/root/
```

Windows 图形界面用户可以用 WinSCP：新建站点 → 填 IP / 账号 / 密码 → 把整个 `lumencafe` 文件夹拖进去。

然后在服务器上 `cd /root/lumencafe`，从第 6 步「改配置」继续。

## 以后怎么更新代码（路线 A 的回报）

本机改完提交后：

```bash

```

```bash
git pull
```

## 常见报错对照

| 报错 | 原因 | 解决 |
|---|---|---|
| push 要账号密码 | 密码认证已禁用 | 用 Personal Access Token |
| clone 卡住 / 超时 | 国内服务器连 GitHub 不稳 | 用 SSH deploy key 方式（22 端口），或服务器上配代理 |
| clone 要密码 | 私有仓库未认证 | 配 deploy key 或用 Token 拼 URL |
| Caddy 签不出证书 | 域名没解析到服务器 | 先确认三条 A 记录生效（`ping 你的域名`） |
| api 容器重启循环 | `.env` 没配或连不上库 | `docker compose logs api` 看具体错 |
