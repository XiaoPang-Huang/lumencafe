# PRD-增量：对话思考模式 + 润色指令按钮 v1.1

> 版本：v1.1（2026-10-18 按用户拍板修订）· 产品经理：许清楚（software-product-manager）
> 基准文档：《PRD-v1.md》v1.1、《架构设计-v1.md》v1.4、《架构定稿-v1.md》。冲突处以架构文档为最高优先级；本文档涉及修订现行决策处见 §6「决策修订清单」。
> 需求来源：用户原话——「我希望对话应用可以支持思考，然后给出一个按钮，可以调用 AI 来润色指令。类似于 workbuddy 的形式，然后设置里面也会有相关模型的思考配置。比如：（添加模型弹窗，高级配置含 工具调用/图片输入/思考模式/自定义协议 勾选；模型选择弹层，含 思考强度 高/超高 选项、上下文窗口、繁忙程度等）。同时是否可以保留专家、skill、mcp 等接入的方式。」
> 业界参考（已检索内化）：Reverie Reasoning mode（per-model 记忆 + 可折叠 Reasoning 面板 + 「Reasoning…」流式态）；Digestible UX 对比（ChatGPT 完成折叠 / Claude 结构化可展开+计时 / DeepSeek 滚动 CoT / Gemini 自主滚动——共识：默认折叠、过程可见不喧宾夺主、thinking… 降感知延迟）；DeepSeek R1 双流协议（`reasoning_content` 与 `content` 分离，先推思维再推正文）；思考档位各家不同（DeepSeek non-think/think-high/think-max、GLM-5 turn-level、Qwen3 thinking budget）→ **本项目档位跟模型官方走，每模型动态配置（v1.1 拍板）**；WorkBuddy（composer 魔棒润色按钮 + 模型弹层思考强度选择 + 左侧功能列，用户指定对标）。

## 2. 产品目标

1. 对话应用支持「思考模式」：模型推理过程以可折叠面板展示（流式期间显示「思考中…」，默认折叠），回答质量可感知提升（G2 的深化：换思考模型/档位零代码）。
2. Composer 内置「润色指令」按钮：一键调用 AI 改写输入框原文，降低表达成本（对标 WorkBuddy 魔棒）。
3. 思考能力可配置：管理端按模型官方能力配置档位列表与默认档，会话内按模型配置渲染档位选择。
4. 对话页左侧功能列提供可扩展入口（新建会话/收藏/专家/Skill/MCP），Skill 经 SkillHub 本期接入；专家/MCP 保留方向、占位先行。

## 5. UI 设计稿描述

### 5.1 思维面板（Thinking Panel）

- **位置**：助手消息卡片内、正文 Markdown 上方。
- **形态**：默认折叠。折叠态 = 一行标题「已深度思考（耗时 Xs）▸」；展开态 = 思维全文，灰阶弱化样式（不得比正文更抢眼）。
- **流式态**：模型开始返回至正文首个 token 到达之间，面板显示「思考中…」+ 轻量动画，计时从请求发起算。
- **历史**：历史消息按 `reasoning` 字段渲染（无则面板不渲染）。

### 5.2 Composer 润色按钮

- **位置**：输入框内右侧（发送按钮旁），魔棒（✨）图标，对标 WorkBuddy。
- **交互**：点击 → loading（禁重复点击）→ 替换输入框原文，焦点保持 → toast「已润色，Ctrl+Z 撤销」。替换后不自动发送。

### 5.3 模型选择弹层（.model-picker 扩展，v1.1 修订）

- 模型项强度行**按该模型 meta 动态渲染**（P0-2）：多档模型显示官方档位按钮组；仅开关模型显示「思考 开/关」；不支持思考的模型不显示。
- 模型项保留 capabilities 徽标；`enabled=true` 时加「支持思考」徽标；上下文窗口读 `meta.context` 展示（Q6 已决：展示）；繁忙程度不展示（无数据来源）。

### 5.4 管理端添加/编辑模型弹窗（v1.1 修订）

- 高级配置区（参照截图1）：「思考模式」勾选（= enabled）；勾选后展开**档位配置子表单**：档位列表（每行 value + label，可增删）+ 默认档下拉（P1-1）。
- 「工具调用 / 图片输入 / 自定义协议」复选框一并渲染但仅落库（P1-1 ⑤），标注「预留」。

### 5.5 左侧功能列 + Skill 面板（v1.1 新增）

- **功能列**：对话页左栏（会话列表）上方，参考 WorkBuddy 红框区；入口 = 新建会话 / 收藏 / 专家 / Skill / MCP（图标 + 文字，当前选中高亮）。手机端窄屏折叠。
- **Skill 面板**：点击 Skill 入口打开侧层面板——上半浏览 SkillHub（搜索 + 列表：图标/名称/描述/安装按钮/已安装标记），安装需二次确认。
- **已安装管理**：「我的 → 应用设置 → 对话 → 已安装技能」：列表 + 开关 + 卸载。应用设置 IA 挂在「我的」域（对齐设置 IA 三域，管理入口属用户级）。
- 专家/MCP：点击打开占位页（「即将上线」空态或禁用按钮）。

## 6. 决策修订清单

> 以下为本文档对现行决策的显式修订。未经列出的现行决策全部维持。

| # | 现行决策（出处） | 修订内容 | 理由与边界 |
| --- | --- | --- | --- |
| R1 | 「调用参数不开放覆盖」（架构设计 Q9：不传 temperature/max_tokens/top_p，一律厂商默认） | **开放一个调用参数维度：`thinking_level`（思考强度）** | 理由：思考模式是本期核心用户价值，业界均以标准参数暴露。**边界**：① 白名单仅 `thinking_level` 一个参数，temperature/max_tokens/top_p 仍不开放（Q9 精神不变）② 仅会话级，无全局默认、无管理页覆盖值 ③ 不触碰系统提示词（Q14 不变；skill 注入走 P1-4 明确通道）④ 透传为空 = 厂商默认 |
| R2 | `chat_messages` 两列结构（content + role）（架构设计 §3.4） | 增列 `reasoning TEXT`（可空） | 思维链需随消息持久化支持历史回看；属正文组成部分，非调用参数 |
| R3 | `POST /chat` SSE 事件仅 `{delta}` / `{error}` / `[DONE]`（PRD §4.6） | 事件流增 `{"reasoning_delta"}` 类型 | DeepSeek R1 双流协议为业界标准；无思维流的模型不产生该事件 |
| R4 | `llm_models.meta` 固定 `{"context","vision","files"}`（架构设计 Q16） | 固定结构增 `reasoning`（v1.1 升级为结构，见 R5）；`tools`/`custom_protocol` 仅预留位 | 能力/档位配置驱动前端强度行显隐；不新增独立表 |
| R5（v1.1 新增） | v1 本文档 P1-1 中 `meta.reasoning` 为布尔 | **`meta.reasoning` 升级为结构 `{enabled: bool, levels: [{value, label}], default_level}`** | 用户拍板「档位跟官方走」：各家档位集合不同（DeepSeek 高/超高、GLM 开关、Qwen budget），固定档位会失真。**边界**：① levels 为空 = 不显示强度选择器（官方仅开关则前端显示「思考 开/关」二态）② label 仅展示用，网关只透传 value ③ `enabled=false` 即完全隐藏强度 UI ④ 默认档必须是 levels 中一项 |

## 7. 专家 / Skill / MCP 接入方式（v1.1 重写）

**结论（v1.1 更新）：Skill 本期实装（SkillHub 接入）；专家、MCP 保留方向、本期占位。**

- **Skill（本期实装）**：SkillHub 面板浏览/安装（P1-4）；安装位置固定在「对话」应用下（用户拍板）；已安装管理在「我的 → 应用设置 → 对话 → 已安装技能」。生效 = 开启的 skill 提示词经 `POST /chat` system 组装处的注入点注入（该注入点 v1 设计为「恒空」，本期被 Skill **部分激活**：仅注入用户已安装且开启的 skill，注入内容来自 skill 包预设 prompt，用户不可改写，不占 R1 白名单——它不是调用参数而是 system 片段）。
- **专家**：本质是「预置 system 片段 + 模型偏好」。注入点已随 Skill 实装，专家未来复用同一通道 + 专家数据管理（本期不做）。
- **MCP**：工具调用协议，落点为网关 `tools` 字段透传 + 后端工具执行器，排序在 Skill 工具化之后；本期功能列仅占位。
- 本期不新建权限点（复用 `app:chat`）；不建专家/MCP 数据表。
