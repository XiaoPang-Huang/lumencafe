# 部署指南 v1（云服务器）

> 结论先行：一台 2核4G 的 VPS 足够。全栈 Docker Compose 四件套（PostgreSQL / FastAPI / Caddy / n8n），Caddy 同域反代 + 自动 HTTPS。三步：装 Docker → 传代码 → 一条 compose 命令。预计 30 分钟。

## 0. 服务器要求

- 配置：2 核 4G 内存、20G 磁盘起步；系统 Ubuntu 22.04 / 24.04 LTS
- 防火墙放行：22（SSH）、80、443；**IP 直连模式还必须放行 8443**（见 §1.1）
- 5432（PostgreSQL）、8000（API）、5678（n8n）**不要**暴露公网，compose 内部走服务名互通
- SSH 建议改用密钥登录，禁用密码登录

## 1. 域名与 DNS

三条 A 记录指向服务器 IP：

| 域名 | 用途 | 是否必须 |
|---|---|---|
| cafe.example.com | 主站（前端 + /api 同域反代） | 必须 |
| api.example.com | 外部客户端直连（OpenAI 兼容 /gw/v1） | 可选 |
| n8n.example.com | 工作流控制台 | 可选 |

域名按实际修改，全文以 example.com 代指。没有域名也能跑：见文末「没有域名」。

### 1.1 备案提醒（重要，先读）

**境内云服务器（腾讯云/阿里云等）会拦截未备案域名的 80 和 443 端口**——公网访问连接被重置，Let's Encrypt 无法完成验证，Caddy 日志报 `Connection reset by peer`。

这里有两个独立的坑，别混为一谈：

1. **访客进不来**：80/443 被拦 → 站点改用 8443 端口提供服务，访客地址带端口
2. **证书签不了**：Let's Encrypt 只在 80（HTTP-01）和 443（TLS-ALPN-01）验证，站点换到 8443 也救不了证书 → 要么走 **DNS-01**（经 DNSPod API 加 TXT 记录验证），要么**放弃域名改用 IP 直连**

#### 当前模式：IP 直连（2026-10-18 起启用）

未备案域名短期无解，而 IP 地址不携带域名信息、不在拦截范围内，所以先用 IP 跑通：

- 访问：`https://134.175.114.81:8443`（保底）；若腾讯云不拦 IP 直连的 443，`https://134.175.114.81` 也可用（待实测）
- 证书：Caddy 内部 CA 自签（`tls internal` + `on_demand`，IP 无 SNI 也能握手，已实测）。加密有效，但浏览器提示「不受信任」，需点一次「高级 → 继续访问」
- 零凭证、零 DNS、零自定义镜像，官方 caddy 镜像即可
- n8n 暂时走 `n8n.lumenhub.online:8443`（有 DNS 记录就能通），急用也可 `http://134.175.114.81:5678`（compose 已发布该端口，带 Basic Auth）

Caddyfile 里 443/8443 双端口监听、内容相同，哪个不被拦截就用哪个；80 端口统一跳 8443。

#### 升级路径 A：域名 + DNS-01（无需备案，浏览器绿标）

四处联动（`deploy/Caddyfile.domain` 是备好的域名版配置）：

1. `cp deploy/Caddyfile.domain Caddyfile`
2. `docker-compose.yml` 的 caddy 恢复 `build: ./deploy/caddy`（带 DNSPod 插件的自定义镜像）
3. `.env` 配 `DNSPOD_TOKEN`（DNSPod 控制台 → 用户中心 → API 令牌 → 创建，格式「ID,Key」）
4. `docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build`

原理：LE 只在 80/443 验证，换端口救不了证书；DNS-01 通过 DNSPod API 自动加 `_acme-challenge` TXT 记录完成验证，完全不依赖入站端口，自动续期。

#### 升级路径 B：ICP 备案（约 2–3 周）

通过后删掉域名版 Caddyfile 各处 `:8443`、`(dns_tls)` 片段和 `import dns_tls`，compose 的 caddy 改回 `image: caddy:2-alpine`，删 `deploy/caddy/` 和 `.env` 的 `DNSPOD_TOKEN`，然后 `up -d --build`。以前备过案（有备案号）可走「接入备案」，快很多。

#### 排查方法

在服务器上执行，别用自己电脑探测（本机代理软件会骗你）：

```bash
curl -sI http://127.0.0.1/health        # 服务器本地通 → 服务没问题，是被拦在公网入口
docker logs lumencafe-caddy-1 --tail 30 # 看 ACME 失败详情
```

日志里出现 `43.174.x.x`（腾讯云 IP）的 `reader size limit exceeded` 或 `Connection reset by peer`，就是被拦截的实锤。

## 2. 安装 Docker

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
docker --version   # 确认安装
```

## 3. 放代码

```bash
git clone <你的仓库地址> lumencafe
cd lumencafe
cp .env.example .env
```

代码怎么从本机推到 GitHub、再拉到服务器（含私有仓库认证、Token 申请、scp 直传备选），见 [从本地上云-v1.md](从本地上云-v1.md)。

## 4. 改 .env（关键项，缺一不可）

| 项 | 怎么填 |
|---|---|
| LUMEN_JWT_SECRET | `openssl rand -hex 32` 生成，必须改 |
| POSTGRES_PASSWORD | 强密码；含 `$` `#` 时值用单引号包住 |
| LUMEN_DATABASE_URL | 密码部分做 URL 编码（@→%40、#→%23、$→%24） |
| LUMEN_INTERNAL_TOKEN | `openssl rand -hex 32`，n8n 抓文献要用 |
| N8N_HOST | 填 `n8n.example.com`（用 n8n 才需要） |
| N8N_ENCRYPTION_KEY | `openssl rand -hex 32`，丢了 n8n 凭据全废，离线备份 |
| DNSPOD_TOKEN | 域名未备案时必填（DNS-01 签证书）；DNSPod 控制台 → API 令牌，格式「ID,Key」 |

LUMEN_CORS_ORIGINS 生产同源访问，留空即可。

## 5. 改域名（仅域名模式需要；IP 直连模式跳过本节）

> 当前默认是 IP 直连模式（根目录 Caddyfile 为 `:443, :8443` 通配站点，无需改域名）。
> 只有切到域名模式（§1.1 升级路径 A）时才需要本节。

编辑根目录 `Caddyfile`（或从 `deploy/Caddyfile.domain` 复制），把 `cafe.lumenhub.online`、`api.lumenhub.online`、`n8n.lumenhub.online` 换成你的域名。注意域名后面带 `:8443`（未备案方案，见 §1.1），换域名时连同端口一起改，且**别删 `import dns_tls` 行**（DNS-01 签证书用）。Caddy 会自动申请并续期 Let's Encrypt 证书。

## 6. 启动

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build
```

启动过程自动完成：跑 Alembic 迁移 → 播种种子数据（含 admin 账号）。首次访问 `https://cafe.example.com` 登录后**立刻改 admin 密码**（.env 里初始值是 `change-me-too`）。

验证（IP 直连模式，`-k` 忽略自签证书告警）：

```bash
curl -k https://134.175.114.81:8443/health                        # {"status":"ok"}
curl -k https://134.175.114.81:8443/internal/jobs/papers-crawl    # 必须 404（内网专用）
```

## 7. n8n 接入（可选，文献每日抓取靠它）

1. 浏览器打开 `https://n8n.example.com`（域名模式）；IP 直连模式下用 `https://n8n.lumenhub.online:8443`，或临时 `http://134.175.114.81:5678`（Basic Auth）。首次进入自建 owner 账号（n8n 2.x 内置用户管理）
2. Workflows → Import from File → 选 `n8n-workflows/papers-crawl.json`
3. 直接 Activate。工作流里的 `X-Internal-Token` 引用 `$env.LUMEN_INTERNAL_TOKEN`，compose 已自动注入，无需手填
4. 之后每天 07:00 自动抓 PubMed 并推送

手动补抓一次（/internal 只开在 compose 内网，从 api 容器内触发）：

```bash
docker exec lumencafe-api-1 python -c "import httpx;r=httpx.post('http://127.0.0.1:8000/internal/jobs/papers-crawl',headers={'X-Internal-Token':'你的LUMEN_INTERNAL_TOKEN'},timeout=300);print(r.status_code,r.text)"
```

## 8. 日常运维

升级（拉代码 → 重建 → 迁移自动跑）：

```bash
git pull
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build
```

备份数据库（建议加 cron 每天一次）：

```bash
docker exec lumencafe-db-1 pg_dump -U lumencafe lumencafe | gzip > ~/backup_$(date +%F).sql.gz
```

看日志 / 看状态：

```bash
docker compose logs -f api
docker compose ps
```

## 没有域名怎么办

改 `deploy/docker-compose.prod.yml`：删掉 caddy 的域名站点，改成：

```caddy
:80 {
	root * /srv/frontend
	file_server
	handle_path /api/* {
		reverse_proxy api:8000 { flush_interval -1 }
	}
}
```

HTTP 明文可跑，但登录令牌走明文网，只建议内网/临时验证用。
