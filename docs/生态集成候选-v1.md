# 生态集成候选 v1（2026-10-24）

> 讨论定稿：三层复用模型 + 触发点清单。原则：**库级随便复用（自研的常规操作）；服务级按需克制（只接"脏活明显更值"的，机器预算 1-2 个新容器）；平台级不碰（产品主权永远在自有 FastAPI + Postgres）。**
> 判断口诀：组件解决的是「我不会写/写不好的脏活」（解析、协议适配）→ 外采值回票价；「我不想写的普通活」（入库、调度、通知）→ AI 写代码更快更省心。
> 机器约束：VPS 现有 db / api / caddy 三件套，新容器按个位数预算（轻量 50MB 级如 n8n→ntfy/Miniflux 随意；重量级 1-2G 如 RAGFlow/Dify 需腾退或升配）。

## 一、定时任务 / 胶水流程

| 候选 | 层 | 结论（2026-10-24 用户拍板） |
|------|-----|------|
| **APScheduler 进程内自研** | 库 | ✅ **当前路线**。定时任务收回后端进程（v1.6 / 修订6 已同步三份契约文档），/internal/jobs/* 保留手动触发口 |
| n8n / Dify / Windmill 等编排平台 | 服务 | ❌ n8n 已移除（维护 workflow 不便）；触发点：定时任务增至 5-10 个、或出现非工程人员要改流程 → 再评估（届时优先 Prefect 其次 Dify） |
| 云函数+定时触发 / GH Actions cron | 服务 | ❌ 代码活在项目外、要回连生产库，不优于进程内 |

## 二、知识库 / RAG

| 候选 | 层 | 触发点 |
|------|-----|--------|
| **pgvector 摘要级自研** | 库/扩展 | ✅ 基线：papers 表加 vector 列，抓取即嵌入，检索一条 SQL 接对话注入点 |
| **RAGFlow**（文档解析最强，HTTP API 完善） | 服务（重） | 上全文 PDF（复杂版面/表格/公式）那天，只买"解析"这一环，主库仍是业务 Postgres |
| FastGPT（中文优化、问答 UI 现成） | 服务（中） | 想要现成问答界面时 |
| Dify 知识库 | 平台 | 仅在为 LLM 编排引入 Dify 时顺带复用，不为 RAG 单独部署 |

## 三、Memory（智能体记忆层）

| 候选 | 层 | 触发点 |
|------|-----|--------|
| **Mem0**（Apache-2.0，自托管，REST/SDK，向量库可挂 pgvector） | 服务（轻） | 对话需要跨会话个性化记忆时——首选候选，与对话 skill 注入点衔接 |
| **octop-memory**（腾讯 Octop 生态，分层召回+全文检索） | 库/服务 | 同上场景，与 Mem0 小规模实测二选一 |
| Zep/Graphiti（时序知识图谱） | 服务+图库 | 需要回答"某事何时为真"才上 |
| Letta | 平台 | 长时自治 agent，锁定成本高，暂不评估 |

## 四、Agent Runtime

| 候选 | 层 | 触发点 |
|------|-----|--------|
| **LangGraph**（MIT，Python 库嵌进 FastAPI） | 库 | ✅ 首选：对话要多步任务/工具调用时，专家/Skill/MCP 注入点现成衔接 |
| smolagents / Pydantic AI | 库 | 简单 agent 场景的轻量备选 |
| Letta server / LangGraph Platform | 服务 | 需要持久化运行、人在环（HITL）时 |

## 五、IM 组件

| 候选 | 层 | 触发点 |
|------|-----|--------|
| **ntfy**（自托管推送，几十 MB） | 服务（轻） | 抓取失败/论文更新推手机——最早可能用到的 IM 能力 |
| **octop-gateway**（腾讯 Octop 生态，一组件桥接微信/飞书/钉钉/QQ/Telegram/Discord） | 服务 | 需要双向 IM（接收指令+推送）时，比逐平台 webhook 省事 |
| 企业微信/飞书/Telegram bot（借道客户端） | API | 只推消息不自建 IM 的最短路径 |
| VoceChat / Tailchat（自建聊天室） | 服务 | 真要在产品内嵌聊天室才上（重量级需求，缓行） |

## 六、文献订阅周边

| 候选 | 层 | 触发点 |
|------|-----|--------|
| **arXiv API 自研抓取** | 自研 | ✅ 当前路线（关键词订阅灵活） |
| Miniflux（RSS 阅读器，20MB，REST API） | 服务（轻） | 想"整学科 RSS 跟进"时：它做轮询/去重，你的应用消费它的 API 入库 |

## 七、其他轻量增强件

- **Uptime Kuma**：工作台状态灯的现成数据源（需要时）；
- **Miniflux 之上的 FreshRSS**：多用户场景才值得（PHP 重 3 倍）。

## 八、关于腾讯 Octop（TencentCloud/Octop，MIT，2026-07 开源）

自托管多用户多智能体 AI 助手平台，功能面是本项目的超集（专家/技能/知识库/子智能体/IM 网关/定时任务）。**不作为底座**（产品重叠 + 主权重叠 + 仅 3 个月大 API 不稳），但四个拆分模块可单独当"工人"评估：`octop-harness`（Agent runtime）/`octop-memory`（Memory）/`octop-gateway`（IM 桥，见上表）/`octop-browser`（CDP 自动化）。其"专家/技能/记忆/网关"的拆分模式验证了本项目同构决策的方向。
