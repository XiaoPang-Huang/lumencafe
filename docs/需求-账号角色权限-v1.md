# 需求：账号 · 角色 · 权限 体系 v1（2026-11-14 用户确认）

> 交接文档：本文档是新会话的开工依据。开工前先读 `AGENTS.md`（项目硬规定）与 `docs/白皮书-v3.md` §12（RBAC 单点拍板）。
> 状态：需求已确认，细节以本文为准；拍板变更先进 `docs/白皮书-v3.md` 再动手。

## 背景与目标

chord 只给身份地基（owner 一次性链接 / invite 邀请链接 / 400 天会话 cookie / principal 两种），**没有账号密码、没有角色、没有权限管理**——这是 chord 官方明确不管的事（白皮书 §04），当初选型时既定策略就是「身份地基用 chord，角色规则自己写、只在网关一处判断」（白皮书 §12）。

目标：建成完整自有的 **账号 + 角色 + 权限** 体系：

- 用户用**用户名 + 密码**登录，不再见任何「链接」；
- 角色至少分**管理员 / 普通成员**，可扩展；
- 权限**到应用级**（对话 / 记账 / 论文 / 管理，每个可设角色门槛）；
- chord 降级为纯会话管道（发 cookie、验会话），账号与规则全部归我们。

## ① 有哪些

### 现状（已存在，可复用）

- chord 提供：`/_chord/owner` 主人链接、`plugins/invite` 成员邀请（POST /_chord/invites 出链接）、`chord-session` cookie（闲置 400 天过期）、principal（owner/member）
- 我们已写：`/api/admin/probe`（owner 判断样板）；对话 / 账本 / 论文数据按用户隔离；agent 工具的 ownerOnly 拦截样板（`beforeToolCall` 角色复核）
- 前端已有：侧栏「管理」组、管理设置空壳页（#/admin）
- 推送通道已有：`src/api/notify.mjs`（企业微信机器人主 + Server 酱备）

### 要建的功能模块

- **M1 账号**：users 表（用户名唯一、scrypt 密码哈希 + 随机盐、显示名、启用/停用）；登录页（用户名 + 密码）；登出；改密（自助）与重置密码（管理员）；登录失败限速
- **M2 角色**：users.role 字段（admin / member 起步）；改角色；管理员保护（至少留一名 admin，不能自降/自删）
- **M3 权限**：应用级开关（chat / money / papers / admin 各自可设「哪些角色可用」）；网关单点中间件统一判断；被拒统一 403；侧栏按权限过滤；直接输 URL 也拦；现有散落的 owner 判断（/api/admin/*、view_push_logs 等）收敛进网关
- **M4 管理页**：用户与角色（参考 Supabase Auth Users 表格 + 行操作：添加、改角色、停用、重置密码；角色权限矩阵参考 thefrontkit）
- **M5 自动发钥匙（并存能力）**：添加成员时可一键生成 chord 邀请链接并经企业微信/Server 酱推送（复用 notify.mjs）——落地前先用它让成员「无感」进系统，落地后作为免密登录的并存选项

## ② 升级顺序（每批独立可验、可停）

1. **批 1 账号登录**：migration users 表 + `src/api/auth.mjs`（scrypt 哈希、限速、登录/登出/改密）+ 自己的登录页（公开路由，替换 app.js 里 `location.replace('/_chord/owner')` 的跳转）；登录验证通过后调用 chord `Sessions.issue` 发 `chord-session` cookie；首个 admin 账号由现有 owner 身份引导创建
2. **批 2 角色 + 网关单点**：role 字段 + 网关中间件；把 /api/admin/*、view_push_logs 等散落的 owner 判断收敛到网关一处；统一 403
3. **批 3 权限矩阵**：应用级开关落库 + 侧栏过滤 + 直访 URL 拦截
4. **批 4 管理页**：用户列表 + 角色权限矩阵（中央弹窗基建，AGENTS.md 规矩）
5. **批 5 自动发钥匙**：邀请链接自动创建 + 推送（可与批 4 合并）

## ③ 影响什么

- **表**：PG 新 `migrations/0005_users.sql`（users 表）；SQLite / chord 数据不动
- **代码**：新增 `src/api/auth.mjs`、登录页（静态资源或 chord 公开路由）、网关中间件、`src/static` 管理页新视图；`plugins/invite` 保留并存（M5 依赖）
- **依赖**：零新增（`crypto.scrypt` 内置）；严禁顺手加库（供应链纪律）
- **兼容**：现有 chord 会话不失效；principal 与 users 映射（owner → 首个 admin）
- **安全**：密码只存 scrypt 哈希；登录限速（如连错 5 次锁 5 分钟）；会话仍 HttpOnly + SameSite=Strict；管理接口全部走网关
- **用户可见**：登录页取代链接；管理页新增「用户与角色」；不再有「used up or expired」

## 验收要点

- 批 1：登录成功 → cookie 生效 → 原全部接口正常；错密码/限速生效；未登录访问受保护接口 401
- 批 2：成员访问 admin 接口 403；代码里 owner 判断只剩网关一处
- 批 3：关掉成员的记账权限 → 侧栏入口消失 + 直访 #/money 被拦 + API 403
- 批 4：管理页全流程 E2E（加人 → 新账号登录 → 改角色 → 停用后登录被拒）
- 全程：E2E 脚本全过、零 JS 错误、`?v=` 已 bump、文档与代码一致、每批单独提交
