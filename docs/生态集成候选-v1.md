# 生态集成候选 v1（2026-10-24）

> 讨论定稿：三层复用模型 + 触发点清单。原则：**库级随便复用（自研的常规操作）；服务级按需克制（只接"脏活明显更值"的，机器预算 1-2 个新容器）；平台级不碰（产品主权永远在自有 FastAPI + Postgres）。**
> 判断口诀：组件解决的是「我不会写/写不好的脏活」（解析、协议适配）→ 外采值回票价；「我不想写的普通活」（入库、调度、通知）→ AI 写代码更快更省心。
> 机器约束：VPS 现有 db / api / caddy 三件套，新容器按个位数预算（轻量 50MB 级如 n8n→ntfy/Miniflux 随意；重量级 1-2G 如 RAGFlow/Dify 需腾退或升配）。

## 一、定时任务 / 胶水流程

| 候选 | 层 | 结论（2026-10-24 用户拍板） |
|------|-----|------|
| **APScheduler 进程内自研** | 库 | ✅ **当前路线**。定时任务收回后端进程（v1.6 / 修订6 已同步三份契约文档），/internal/jobs/* 保留手动触发口 |
| n8n / Dify / Windmill 等编排平台 | 服务 | ❌ n8n 已移除（维护 workflow 不便）；触发点：定时任务增至 5-10 个、或出现非工程人员要改流程 → 再评估（届时优先 Prefect 其次 Dify） |
| 云函数+定时触发 / GH Actions cron | 服务 | ❌ 代码活在项目外、要回连生产库，不优于进程内 |

## 八、关于腾讯 Octop（TencentCloud/Octop，MIT，2026-07 开源）

自托管多用户多智能体 AI 助手平台，功能面是本项目的超集（专家/技能/知识库/子智能体/IM 网关/定时任务）。**不作为底座**（产品重叠 + 主权重叠 + 仅 3 个月大 API 不稳），但四个拆分模块可单独当"工人"评估：`octop-harness`（Agent runtime）/`octop-memory`（Memory）/`octop-gateway`（IM 桥，见上表）/`octop-browser`（CDP 自动化）。其"专家/技能/记忆/网关"的拆分模式验证了本项目同构决策的方向。逐组件深评见《Octop组件评估-v1.md》（2026-10-24，结论：四个都暂不引入，触发点保留）。

## 九、增补候选（2026-10-24 第二批，待拍板）

> 应「还有哪些开源组件/服务可用」追问增补；候选现状均已逐条核实。层级判定照旧三层模型 + 判断口诀。
> 许可证是本节新立的硬约束，见 9.7。

### 9.1 对话能力（离第一/二批功能最近）

- **SearXNG**（服务·轻：<256MB + Redis 30MB）：自托管元搜索，JSON API 免 key 免查询费，给对话挂「联网搜索」——对标 DeepSeek 界面的标配功能。
  - 脏活判定：搜索引擎聚合适配是脏活 → 外采值回票价。
  - 坑位：settings.yml 要开 `formats: [html, json]`（默认只有 HTML，API 一律 403）；私用要把限流器放宽；上游引擎可能封 IP，靠多引擎轮换兜底。
  - 触发点：对话要联网搜索那天。**本批最可能先用上的服务。**
- **FastMCP**（库·Apache-2.0，约 23k stars，Prefect 维护）：MCP server/client 框架。装饰器十行把我们的能力（记账查询、文献检索、网关管理）暴露成 MCP 工具；也能当客户端接外部 MCP。
  - 配套价值：第三方现成 MCP server（如 MinerU 自带的）可直接挂进我们的 MCP 注入点。
  - 坑位：版本跑得快（1.x → 4.x），必须锁版本；官方 `mcp` SDK 是依赖更小的备选（API 不通用）。
  - 触发点：Skill 中心 / MCP 注入点立项那天。**库级随便用。**
- **trafilatura**（库）：网页正文/元数据提取，收藏剪藏从 HTML 抠正文（备选 readability-lxml）。
  - 触发点：收藏功能动工。

### 9.2 文献解析（细化 §二「上全文 PDF」触发点）

- **优先路线：arXiv LaTeX 源码**（e-print 源码包）✅：arXiv 论文大多附 LaTeX 源码，直接解析比任何 PDF 解析器都准，零模型零 GPU。PDF 解析只留给无源码/非 arXiv 文档。届时首选这条。
- **Docling**（库·MIT，IBM）：PDF→版面/表格/阅读顺序结构化；模型小（258M）CPU 可跑；LangChain/LlamaIndex 集成成熟。公式识别弱于 MinerU。**MIT 许可证对本项目最干净。**
- **MinerU**（进程/服务级）：公式、复杂表格、中文排版最强（2026-08 十二维横评 11 项通过）；自带 MCP server。但重（模型缓存 20GB 级，最好 GPU）+ 许可证非纯 Apache（附加条款/AGPL 说法，用前读 LICENSE）→ **只做独立进程网络调用，不库级嵌入**。VPS 无 GPU，只能 CPU 慢速模式，真要上量需单独算力。
- **zhparser / pg_jieba**（PG 扩展·零容器）：中文词级全文检索（记账备注搜索等），补 pgvector 语义检索的空白。
  - 触发点：站内搜索要中文分词那天。

### 9.3 模型网关周边（网关已自研，只补不换）

- **LiteLLM**（库/代理·MIT）：140+ provider 的 API 差异适配，正是「各家接口不一致」这块脏活的外采答案。现在 llm_gateway 自研适配够用；provider 膨胀到十几家再回头看，优先 Python 库模式嵌入适配层，不换网关本体。
- **one-api / new-api**（服务）：不引入（主权重叠）。只抄设计——后台的「令牌额度 / 倍率计费 / 用量报表」是 gateway_tokens 额度功能的现成参考（one-api 已是 AGENTS.md 的渠道管理参考对象）。new-api 比 one-api 活跃但 AGPL。

### 9.4 账号与文件（触发点备着）

- **Casdoor 或 Logto**（服务）：微信扫码 / 第三方 OAuth 登录的协议脏活。触发点：开放注册或微信登录立项。现在 JWT 自研够用。
- **MinIO**（服务）：S3 对象存储。触发点：附件/文献原文/图片规模化，或多机部署。现在本地磁盘 + Caddy 够。

### 9.5 运维可靠性

- **restic**（CLI·BSD）：增量加密去重备份，`pg_dump + restic` 异地一份，比自研备份脚本稳。**用户数据上线前就该配——本批唯一「现在就值得」的。**
- **GlitchTip**（服务·轻）：Sentry 兼容错误追踪。触发点：用户多了翻日志定位不过来。
- **Beszel**（服务·轻）：服务器资源监控，工作台状态灯数据源；与 Uptime Kuma 互补（一个管服务活着没，一个管机器扛不扛得住）。
- **Langfuse**（服务·重）：LLM 调用追踪/成本/prompt 版本/评估。触发点：多用户计量或 prompt 迭代要实验对比。重量级（v3 需 ClickHouse 等），要腾机器预算才上。

### 9.6 明确不引入

- 完整 LLM 应用平台（Dify / FastGPT / LobeChat / Open WebUI）：平台级不碰，照旧只当 UI 参考。
- Agent 框架再横跳（AutoGen / CrewAI 等）：LangGraph 既定。
- Keycloak / Authelia：身份全家桶太重，家庭/小团队用不上。
- Grafana / Prometheus 全家桶：超机器预算，9.5 的轻量组合够用。
- Ollama 本地推理：VPS 无 GPU，不现实。
