## 2. 总体架构

```
浏览器（手机/电脑/PWA）
   │ HTTPS
Caddy ── 静态托管 React 构建产物 │ 反代 /api │ SSE 不缓冲
   │
FastAPI ──┬─ 平台层：账号/RBAC、应用注册表、模型管理
          ├─ 应用 API：打卡 心情 文献 量表 知识库…
          ├─ AI 网关：对话 SSE / 解读（DeepSeek/Kimi/OpenAI 兼容端点）
          └─ 定时任务：文献抓取、每日备份
   │
PostgreSQL（user_id 行级隔离；未来 pgvector = 知识库）
   │
n8n（后装；仅自动化编排，与对话无关，不直连数据库）
```

技术栈：Vite + React + TS + shadcn/ui + Tailwind（一套代码手机/电脑自适应）。

## 3. 账号与权限（RBAC）

- 三件套分离：`users`（账号：用户名+密码 bcrypt）、`roles`（admin/member）、`permissions`（权限点，如 `app:chat`、`admin:users`、`admin:models`）+ `user_roles`、`role_permissions` 关联表；
- 后端用依赖注入做校验：`require_permission("admin:models")` 装饰器；
- v1 只设两个角色，表结构按可扩展设计（权限点驱动，不写死角色判断）；
- 登录 JWT 30 天过期，无 refresh token；忘记密码 = 管理员后台重置；
- 注册开关：环境变量 `REGISTRATION_OPEN=false`（默认关），实例部署者自行开启。

## 4. 模型管理（参考 Dify / LobeChat 的方案）

- **Provider 抽象**：一个 provider = 名称 + base_url + API Key + 类型（OpenAI 兼容即可覆盖 DeepSeek/Kimi/其他）；
- **模型配置**：每 provider 下挂模型清单，参数含 temperature / max_tokens / top_p；
- **应用级覆盖**：每个对话应用绑定（provider, 模型, 系统提示词, 参数覆盖），存 settings 式键值或独立表；
- **管理页**：仅 admin 可见；Key 存库（自部署威胁模型低），环境变量作初始默认值；
- 后端读取配置 → 调对应端点；对话接口完全配置驱动。

## 6. 数据、文件与备份

- 业务数据全部 PostgreSQL，user_id 行级隔离（现状已如此）；
- 文件（知识库文档、头像等）先存服务器本地目录；COS 列为可选；
- 备份：每日 pg_dump → 压缩 → 本地保留 7 份（可选同步 COS）；时间用设置项 `backup_time`；
- 开源前必须补 Alembic 迁移（替代 create_all）。

## 7. 自动化：FastAPI 任务 vs n8n

- **FastAPI 任务**（进程内调度器）：数据密集、要事务/幂等——文献抓取（已有 crawler 模式）、每日备份；
- **n8n**（后装，~0.3G）：胶水型、规则常变——生活提醒、跨服务通知；通过 HTTP 调 API 拿数据，**不直连数据库**；
- n8n 是**自动化编排工具**：浏览器打开即是可视化画布，左侧节点库（定时/Webhook/HTTP/邮件/AI…）拖出来连线即成流程，有执行历史和重试；它不是对话引擎，对话应用与它无关。
