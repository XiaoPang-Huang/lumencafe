# 06 · 风格设计指南——从 RAGFlow 提炼的可复用设计规范

> 用途：供流光咖啡馆项目重新设计时直接参考的规范手册。
> 每条注明「直接采用 / 改造后采用 / 不建议采用」的建议。

## 1. 设计 token 层（直接采用这套结构，换色值即可）

RAGFlow 最值得抄的不是颜色，而是 **CSS 变量 → Tailwind 映射 → 组件引用** 的三层 token 架构：

```
tailwind.css 定义语义变量（--bg-base / --text-primary / --border-default ...）
tailwind.config.js 把变量映射为颜色类（bg-bg-base / text-text-primary ...）
组件只写语义类，不写死颜色 → 深浅色双主题零成本
```

**改造后采用**：流光咖啡馆已有红白灰体系（品牌红 `#D92D20`、石墨灰 `#2E2E33`、深炭 `#1F2329`、白卡浅灰页 `#F4F4F5`）。把 RAGFlow 的 token 结构套进来、替换色值——即「**RAGFlow 的骨架 + 我们的红白灰**」。

建议 token 表（对照关系）：

| RAGFlow token | 流光咖啡馆对应 |
|---|---|
| `--bg-base` 页面底 | `#F4F4F5` 浅灰页 |
| `--bg-component` 组件/卡底 | `#FFFFFF` 白卡 |
| `--bg-card` 5% 黑灰底 | `rgba(31,35,41,0.05)` |
| `--text-primary` 主文字/主按钮 | `#1F2329` 深炭 |
| `--text-secondary` | `rgba(31,35,41,0.6)` |
| `--accent-primary` 青绿 | `#D92D20` 品牌红（点缀位） |
| `--state-error/success/warning` | 红 #D92D20 / 绿 #00B42A / 橙 |
| 主按钮 | 深炭底白字（同 RAGFlow 近黑主按钮）|

关键原则照抄：**主按钮用近黑（深炭），品牌红只做点缀**（选中态、关键数字、accent 按钮）——与 2026-11-14 已定「红仅主按钮/选中态/关键数字」的规则衔接（RAGFlow 证明了「黑主按钮 + 点缀色」的耐看性，可缓解「红主按钮太炸」的风险，建议主按钮改深炭、红降为强调位，与用户再拍板）。

## 2. 字体与字号

- **直接采用**：单一无衬线字体全站 + 本地 woff2 自托管；14px 基础字号；标题阶梯 `text-2xl/20px bold → text-xl semibold → text-lg medium`。
- 流光现有 Manrope + MiSans→PingFang 链保留，参考 RAGFlow 的 Inter 多字重本地打包方案（可变字体优先，回退静态字重）。

## 3. 圆角 / 边框 / 间距规范

| 项 | RAGFlow 值 | 建议 |
|---|---|---|
| 圆角阶梯 | 4/5/6/7/8/10/12/16px | 直接采用（比自己随意取整更细） |
| 特色细边框 | **0.5px** | 直接采用（卡片描边质感关键） |
| 按钮高 | 24/28/32/40/48 | 直接采用，主按钮 32px (default) |
| 卡片网格 | gap-6，1→5 列响应式 | 直接采用（配合「容器卡拉满宽度」拍板） |
| 页面边距 | px-5 pt-8 | 直接采用 |
| 滚动条 | 细、悬浮显形 | 直接采用 |
| 侧栏宽 | 64/240 折叠展开 | 直接采用 |

## 4. 组件规范

### 4.1 按钮（改造后采用）

抄变体**结构**（Solid/Outline/Ghost 三系列 + 危险态成对出现），换我们的配色：

- default：深炭底白字；hover 90% 不透明（RAGFlow 的 /90 技巧直接抄）。
- accent：品牌红底白字，**全站克制使用**。
- destructive / danger-hover 成对：删除按钮平时中性、hover 变红——这个「危险延迟暴露」设计直接采用，比常驻红按钮优雅。
- 内建 loading / dot / block 三个行为位，直接采用。

### 4.2 反馈三件套（直接采用）

- Toast：顶部居中 2.5s。
- 删除确认：单一确认组件 + 全站复用（我们的 modal 基建已符合）。
- 复制成功：图标变绿勾 2 秒。

### 4.3 空态（直接采用）

**空态卡 = 创建入口**：480px 虚线卡 + 居中大号 Plus，整卡可点击；区分「全空」（可点）与「搜索无结果」（不可点）两态。配合 `?isCreate=true` URL 深链自动弹创建框。

## 5. 信息架构规范（直接采用）

1. **资源同构**：所有「对象集合」共用一套列表骨架（筛选栏 + 响应式网格 + 分页 + 空态）。流光的应用中心/收藏/技能中心照此。
2. **导航三件套**：主导航记组（≤7 项）→ 组内胶囊页签 → 详情页次级侧栏页签；`activeAliases` 别名保高亮（**路径段边界匹配**，防 `/chat` 误亮 `/chat-channel`）。
3. **详情页沉浸联动**：进入详情自动折叠主导航腾空间，退出恢复。
4. **列表页筛选按钮带计数徽标**：有激活筛选时按钮变形 + 数字徽标。

## 6. 对话体验规范（直接采用，与我们已定的 chat 域高度相关）

1. **URL 即会话状态**：`?conversationId=` 可分享/刷新/回退。
2. **会话懒创建**：发送时才落库。
3. **模块级流式 store**：切页流不停 + LRU 缓存（10 会话）+ 流式会话防驱逐 + hydrate 防截断守卫。
4. **60ms 节流写渲染**：SSE chunk 合并后按帧批量更新，Markdown 不全量重渲。
5. **思维链 `<details>` 折叠块**；**引用三级呈现**（行内标记 → 悬浮原文 → 点击定位 PDF）；**停止键复用发送位**；**失败问题回填输入框**。
6. **操作条 hover 显形**（opacity 过渡），保持界面安静。

## 7. 表单与流程规范

1. **react-hook-form + zod**，条件字段用 `superRefine` 互斥校验（比我们手写判断干净）。
2. **Enter 提交排除输入法合成态**（`isComposing`）——中文输入必踩坑，直接采用。
3. **草稿/提交双缓冲**：弹窗内多次选择、关闭时才提交（RAGFlow 的检索过滤 Popover 模式），适用于任何「选择器 + 触发重查」场景。
4. **状态机 UI 完整五态**：运行中（进度+取消）/ 取消中（遮罩 scrim）/ 排队（时钟）/ 成功 / 失败（日志卡 + ERROR 高亮）。

## 8. 不建议直接采用 / 需要按自身情况裁减

| 项 | 理由 |
|---|---|
| 近黑底 + 青绿点缀的配色本身 | 我们有红白灰体系，只抄结构不抄颜色 |
| API Key 明文展示 | 个人工具可接受，多用户产品应脱敏 |
| Remember me 纯 UI 占位 | 假功能，勿学 |
| 无建议问题 chips 的新会话引导 | 对我们 chat 应用反而是可补的增强点 |
| `/admin` 完全无入口隔离 | 便于安全，但需记得给管理员留直达方式 |
| 新旧 token 双轨并存 | RAGFlow 自己也在迁移中，我们直接只建一套新 token |
| 列表页 5 列密度上限 | 视内容复杂度，2xl 屏可收到 4 列 |
