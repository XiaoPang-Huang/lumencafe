**环境注意事项（开发会话必读）**：

- 验证 Node 版本必须用 `nvm list` 或 `D:\nodejs\node.exe -v`——PATH 里 WorkBuddy 自带 Node 22 排在前面，`node -v` 在 AI 沙箱里可能显示错版本。
- `wsl.exe` 在 WorkBuddy 沙箱黑名单，AI 不能执行 wsl 命令；需要时让用户跑。
- PG 容器数据卷挂 `/var/lib/postgresql`（**不是** `/data`），卷名 `pgdata`，库名 `lumencafe`，口令 `dev-only-change-me`。
- 容器重启：`docker start pg`；健康检查：`docker exec pg pg_isready -U postgres`。
- Docker 已清理：只剩 pg 容器 + pgvector 镜像 + pgdata 卷（旧 Python 栈容器/镜像/卷/网络/构建缓存全部删除，回收约 6GB）。

## 2. 第 0 批 · 程序骨架

### 0A npm 骨架 + 主程序最小启动

**做什么**：

1. 根目录建 `package.json`：`type: module`，engines `node >=22.19.0`，依赖精确锁版本（禁 latest）：
   - `@earendil-works/pi-ai@1.5.2`
   - `@earendil-works/pi-agent-core@1.5.2`
   - `@earendil-works/pi-durable@1.5.2`
   - `@earendil-works/pi-schema@1.5.2`
   - `@earendil-works/chord@1.5.2`
   - `esbuild@0.28.2`、`ws@8`（`chord/app` 的可选依赖，白皮书 §03 已核实）
2. `npm install` 生成 lockfile，检查 0 漏洞。
3. 建 `src/server.mjs`：用 `chord/app` 的 `startServer` 起最小主程序（读 `.env` 的端口约定，开发默认 8480 起自选，写进 `.env` 的 `PORT`）。
4. 目录骨架一次立好（空目录放 `.gitkeep`）：

```
src/
  server.mjs        # 入口：startServer 装配
  gateway/          # 唯一 RBAC：路由鉴权 + 工具调用前复核（§06）
  apps/             # chat/ money/ papers/ 三应用模块
  jobs/             # 慢活 worker（第 3 批起用）
  static/           # 前端静态文件（0C 填充）
migrations/         # PG 建表脚本（0B 起用）
```

**验证**：

- `npm ls` 五个 pi/chord 包全部显示 1.5.2；
- 启动后控制台打印主人登录链接（形如 `http://127.0.0.1:PORT/_chord/owner#<token>`）；
- 浏览器打开该链接能登录；未带身份访问其他路由返回 401（chord 默认拒绝）；
- 白皮书 §03 已实测过此行为（2026-11-11），照抄即可。

**提交**：`feat(骨架): chord 主程序最小启动 + 精确锁版本`

### 0B 存储接入

**做什么**：

1. `migrations/0001_init.sql`：最小建表（users 业务侧扩展列、审计占位即可，业务表随各批加）；PG 连接层 `src/db.mjs`（读 `.env` DATABASE_URL）。
2. 启动流程：连 PG → 跑未执行的 migration（自建简易版本号表即可，不引入 ORM）→ 起 chord 服务。
3. SQLite 框架态（登录/会话/对话记录/pi-durable 检查点）用 chord 自带，不自己管（§05 方案 A）。
4. 业务待办表放 PG（Q17 已拍板），本批只建表结构，不实现调度。

**验证**：

- 删库重建能一键恢复：`docker exec pg psql -U postgres -d lumencafe -c "\dt"` 显示迁移表；
- 主程序启动日志显示 PG 连接成功 + migration 版本号；
- PG 挂掉时主程序报错退出（fail fast），不静默。

**提交**：`feat(存储): PG 连接层 + migration 机制`

### 0C 页面外壳

**做什么**：

1. 前端形态照 `prototype/v2`（§15 已拍板）：单页应用、hash 路由、静态文件由主程序直接发（chord 静态目录指向 `src/static/`）。
2. 视觉照 AGENTS.md 设计强制规则：Meta 蓝 #0064E0、Manrope + MiSans、毛玻璃、容器卡拉满宽度；参考 gethomepage / Homarr / midday / Open WebUI / macOS 设置。
3. 页面：登录态检测 → 工作台空壳（卡片网格占位）+「我的」（三域入口：通用/应用/管理设置）。
4. 功能面板一律中央弹窗（`<dialog class="modal-mask">` 基建），不做侧抽屉。
5. 改静态资源必须 bump `?v=` 版本号。

**验证**：

- 浏览器登录后看到工作台空壳 +「我的」骨架；
- 未登录访问跳登录；成员角色进不了管理页（第 1 批前先用两个测试账号验证 401 行为）；
- 手机宽度下卡片布局正常（双端同一套）。

**提交**：`feat(外壳): 单页应用骨架 + 登录态 + 三域入口`

**每批固定流程**（AGENTS.md）：需求确认 → 业界参考检索 → 原型拍板 → 白皮书同步（`npm --prefix=tools run docs:build`）→ 开发 → 验收（含时序图逐条比对拍板原文）→ 提交。

**全批硬约束**：

- 判活规矩（§08）：步骤说不准的活才用 pi agent；步骤固定直接单次 LLM 调用。
- RBAC 只在网关一处判断，禁止散进应用。
- 慢活：写数据 + 记待办同一次事务；后台并发 1–2；任务幂等；不用 Redis/消息队列。
- 版本钉死禁 latest；升级先出影响面评估（§14）。
- 推送走企业微信群机器人主 + Server 酱备，禁个人号逆向。
- 金额一律「分」；记账配色收入红支出绿。
